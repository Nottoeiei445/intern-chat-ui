## 📌 Structure Architecture: Feature-Based Structure

> **วัตถุประสงค์:** แยกซอร์สโค้ดตามกลุ่มหน้าที่ของโมดูล (เช่น ระบบแผนที่ ระบบแชท ระบบยืนยันตัวตน) เพื่อให้โค้ดแยกขาดจากกันอย่างสมบูรณ์

* **การจัดวางโครงสร้างโฟลเดอร์หลัก:**
  * `src/app`: จัดการระบบเส้นทาง (Routing) และโครงสร้างหน้าเว็บ (Layout)
  * `src/components`: จัดเก็บคอมโพเนนต์ส่วนกลางที่ใช้ซ้ำ และ UI พื้นฐานจาก shadcn/ui
  * `src/features`: โมดูลหลักของแอปพลิเคชัน (แยกกลุ่มโฟลเดอร์ เช่น `map`, `chat`, `auth`) ภายในมี `components`, `services`, `hooks`, และ `types` ของตัวเอง
  * `src/lib`: ฟังก์ชันช่วยเหลือและคอนฟิกูเรชันส่วนกลางที่แชร์ร่วมกันทั่วทั้งแอปพลิเคชัน
  * `src/store`: ระบบบริหารสถานะส่วนกลางประจำแอปพลิเคชันผ่าน Zustand ทำหน้าที่เป็นท่อส่งข้อมูลสากลแชร์สเตตข้ามโมดูล
  * `.env.local`: จัดเก็บค่าตัวแปรสภาพแวดล้อมที่เป็นความลับ (ถูกยกเว้นจากการอัปโหลดขึ้น GitHub)

## 📂 โครงสร้างภายใน src/app (Routing & Layout)

### 📄 layout.tsx (Root Layout)
>  กำหนดโครงสร้างนอกสุดของแอปพลิเคชัน คุมระบบฟอนต์หลัก และติดตั้ง Global Providers ครอบทั้งระบบ

* **กลไกสำคัญ:**
  * เรียกใช้งาน `ThemeProvider` (บังคับระบบเป็น Dark Mode), `ToastProvider` (ระบบแจ้งเตือนป๊อปอัพ), และ `AuthProvider` (จัดการเซสชันผู้ใช้งาน)

### 📄 page.tsx (Main Workspace)
>  หน้าแรกของระบบ ทำหน้าที่จัดเลย์เอาต์หน้าจอแผนที่หลัก และใช้สเตตควบคุมการพับเปิด-ปิดแผงแชทฝั่งซ้าย

* **คอมโพเนนต์หลักที่เรียกใช้:**
  * `<MapDashboard />` (จาก `src/features/map`) -> โหลดเอนจินแผนที่ MapLibre GL JS เรนเดอร์ข้อมูลเชิงพื้นที่
  * `<ChatFeature />` (จาก `src/features/chat`) -> อินเตอร์เฟสกล่องข้อความแชทสำหรับส่งคำสั่งไปประมวลผลกับ AI
  * `<MapLegend />` (จาก `src/features/map`) -> แผงคำอธิบายสัญลักษณ์และขอบเขตสีเลเยอร์ (พิกัดขยับหลบแผงแชทออโต้)
  * `<AuthWidget />` (จาก `src/features/auth`) -> วิดเจ็ตแสดงข้อมูลโปรไฟล์และสถานะบัญชีผู้ใช้งาน
  * `<LayerManager />` (จาก `src/features/map`) -> หน้าต่างจัดการเปิด-ปิด และนำเข้า/ส่งออกข้อมูลเลเยอร์บนแผนที่

## 📂 โครงสร้างภายใน src/lib (Shared Utilities)

### 📄 api-client.ts (ระบบจัดการ Network Request)
>  โมดูลจัดการสตรีมข้อมูลและการเชื่อมต่อ HTTP Request กับระบบเซิร์ฟเวอร์หลังบ้านทั้งหมด ยุบลอจิกซ้ำซ้อนมารวมไว้ที่เดียว

* **กลไกสำคัญ:**
  * **Interfaces:** ควบคุมโครงสร้างข้อผิดพลาดผ่าน `ApiError` (extends Error) รองรับ `status` และก้อนข้อมูลรายละเอียด `data`
  * **Internal Config:** มี `BASE_URL` ดึงค่ามาจาก `ENV.CHAT_API_BASE_URL` (มี Fallback เป็น `http://localhost:3000`) และตั้งชุดหัวข้อมาตรฐาน `DEFAULT_HEADERS` บังคับส่งแบบ `application/json` พร้อมข้ามหน้าเตือนของ ngrok
  * ฟังก์ชัน `getToken()`: ดึงรหัสยืนยันสิทธิ์ (`access_token` หรือ Guest Token) ออกจากคุกกี้
  * ฟังก์ชัน `buildUrl()`: ประกอบโครงสร้าง URL ปลายทางอย่างปลอดภัย ตรวจสอบ Regex ป้องกัน Path ซ้ำซ้อน และลูปพ่น Query Parameters พ่วงท้ายอัตโนมัติ
  * ฟังก์ชัน `requestRaw()`: ฟังก์ชันระดับล่างสุดเรียกใช้ `fetch` โดยตรง มีกลไกแอบแนบ `Authorization: Bearer <token>` อัตโนมัติ และแปลงร่าง Body Payload เป็น JSON String
  * ฟังก์ชัน `request()`: ตัวจัดการ Request หลัก (High-level Wrapper) รับช่วงต่อจาก `requestRaw` ทำหน้าที่แปลงข้อมูลดิบเป็น JSON หาก `res.ok` เป็นเท็จ จะพ่น Log Debug และ `throw ApiError` ทันที
  * **เมธอดสำเร็จรูปที่ Export ให้ใช้งาน:** `apiClient.get`, `apiClient.post`, `apiClient.put`, `apiClient.patch`, `apiClient.delete` และ `apiClient.stream` (ยิงคำสั่งพิเศษเชื่อมต่อรับส่งข้อความแชท AI แบบ Real-time Streaming ส่งกลับเป็น `Response` ดิบไปแกะท่อสตรีมต่อเอง)

### 📄 env.ts (ระบบคุมความปลอดภัยสภาพแวดล้อม)
>  โมดูลศูนย์กลางการบริหารจัดการค่าตัวแปรสภาพแวดล้อม (ENV) เพื่อให้เกิดระบบตรวจสอบชนิดข้อมูลและความปลอดภัยสูงสุดขณะเขียนโค้ด

* **กลไกสำคัญ:**
  * **Global Type Declarations:** ขยายเนมสเปซของ `NodeJS.ProcessEnv` เพื่อล็อกรายชื่อคีย์ความลับทั้งหมดเข้ากับระบบตรวจสอบของ TypeScript Type Safety รองรับ Autocomplete เต็มรูปแบบ (เช่น `NEXT_PUBLIC_COMPANY_API_KEY`, `NEXT_PUBLIC_CHAT_API_BASE_URL` เป็นต้น)
  * **Exported Object:** ส่งออกออบเจกต์ `ENV` (as const) เป็นวัตถุอ่านได้อย่างเดียว (Read-only) ป้องกันการพิมพ์ชื่อคีย์ผิดพลาด

---

### 📄 storage.ts (โมดูลบริหารจัดการหน่วยความจำบราวเซอร์)
>  คลังเครื่องมือเก็บันทึกข้อมูลค้างสถานะไว้บนเว็บไคลเอนต์ โดยแบ่งแยกสถาปัตยกรรมออกเป็น 2 ส่วนตามระดับความปลอดภัยข้อมูล

* **กลไกสำคัญ:**
  * **ฝั่ง Cookie (สำหรับเก็บสิทธิ์ Token):** ทำงานร่วมกับแพ็กเกจ `js-cookie` บังคับสโคปพิกัด Root Path ที่ `/` ประกอบด้วยฟังก์ชัน `storage.getCookie`, `storage.setCookie` (ตั้งเวลาหมดอายุออโต้รูปแบบมิลลิวินาที) และ `storage.removeCookie`
  * **ฝั่ง LocalStorage (สำหรับข้อมูลการตั้งค่าทั่วไป):** มีระบบดักจับ SSR Safeguard (`typeof window === "undefined"`) กันสคริปต์ระเบิดขณะเรนเดอร์ฝั่งเซิร์ฟเวอร์ ประกอบด้วยฟังก์ชัน `storage.getLocal` (เช็กแปลงค่า JSON อัตโนมัติ), `storage.setLocal` และ `storage.removeLocal`

---

### 📄 utils.ts (แหล่งรวมเครื่องมือสนับสนุนสากล)
>  คลังรวมฟังก์ชันคอยช่วยเหลือการทำงานส่วนกลาง (Helper Functions) ที่ไม่มีเรื่องของ Business Logic เข้ามาเกี่ยวข้อง

* **กลไกสำคัญ:**
  * ฟังก์ชัน `cn(...inputs: ClassValue[])`: ผสมผสานและประกอบร่างชื่อคลาสสไตล์ CSS สำหรับ Tailwind CSS รับอาร์กิวเมนต์เข้าไปปั่นรวมกันผ่านระบบเงื่อนไขของ `clsx` จากนั้นส่งต่อให้ `twMerge` สแกนลอกคราบคลาสที่เขียนชนกัน (Class Conflict) ให้ผลลัพธ์สุดท้ายเป็นสตริงคลาสที่ถูกต้องไม่แสดงผลเพี้ยน

## 📂 โครงสร้างภายใน src/store (Global State)

### 📄 useMapStore.ts (ระบบจัดการสถานะส่วนกลางประจำแอปพลิเคชัน)
>  โมดูลบริหารจัดการสถานะส่วนกลางด้วย Zustand ควบคุมระบบแผนที่ สถิติเลเยอร์พิกัดเชิงพื้นที่ ข้อมูลสิทธิ์เข้าถึง API คีย์ และเชื่อมโยงลอจิกการส่งข้อมูลข้ามโมดูลร่วมกับระบบแชท

* **กลไกสำคัญ:**
  * **Interfaces & Types:** รองรับโครงสร้างข้อมูล `PendingChatData` สำหรับเก็บข้อความสั่งแชทและอาเรย์รูปภาพ Base64 ชั่วคราว และอินเตอร์เฟสหลัก `MapState`
  * ฟังก์ชัน `setMap(map)`: บันทึกและส่งมอบสิทธิ์ระบบควบคุมแผนที่ (Map Instance) ขึ้นสู่ Store ส่วนกลาง เรียกทำงานอัตโนมัติเมื่อแผนที่เริ่มระบบและโหลดเอนจิน MapLibre GL JS สำเร็จ เปิดทางให้โค้ดฟังก์ชันจับ Event (`useMapEvents`) สามารถเข้าถึงพิกัดละติจูด/ลองจิจูดที่ User คลิกเพื่อสั่งเปิดหน้าต่างป๊อปอัพได้ถูกตำแหน่ง
  * ฟังก์ชัน `setDynamicLayers(layers)`: อัปเดตเปลี่ยนแปลงรายการ Layer ทั้งหมดใน Store เรียกทำงานเมื่อนำเข้าเลเยอร์ใหม่จากแชท AI หรือแก้ไขรายการ เพื่ออัปเดตคอมโพเนนต์แผนที่และ `<MapLegend />`
  * ฟังก์ชัน `toggleLayerVisibility(layerId)`: สลับสถานะซ่อน/แสดงเลเยอร์ โดยเพิ่มหรือลบรหัสออกนอกอาเรย์ `hiddenLayers` เพื่อปรับคุณสมบัติการเรนเดอร์ของ MapLibre
  * ฟังก์ชัน `toggleBaseMap()`: สลับค่าสถานะ Boolean ของ `isBaseMapVisible` เพื่อเปิดหรือปิด Base Map Background ให้ผู้ใช้งานซ่อนรายละเอียดพื้นหลังและโฟกัสเลเยอร์ Heatmap หรือกราฟิกเชิงพื้นที่ได้ชัดเจนขึ้น
  * ฟังก์ชัน `setActiveStyle(layerId, styleKey)`: ค้นหาวัตถุเลเยอร์เพื่อเปลี่ยนค่าคุณสมบัติสไตล์ที่เปิดใช้งาน (`activeStyleKey`) ตามคำสั่งเหตุการณ์ `map_style` ที่ระบบหลังบ้านยิงสตรีมกลับมา
  * ฟังก์ชัน `updateLayerHistoryCount(chatId, layerId, action)`: คำนวณปรับเปลี่ยนตัวเลขสถิติจำนวนประวัติการเปลี่ยนแปลงเลเยอร์ภายในออบเจกต์ `layerHistoryCount` ทุกครั้งเมื่อเกิดกิจกรรมปรับแต่ง เปลี่ยนค่า หรือลบสถานะของเลเยอร์ในห้องแชท
  * ฟังก์ชัน `setApiKey()` / `clearApiKeys()`: จัดเก็บหรือล้างข้อมูล API Key ของผู้ให้บริการภายนอก (เช่น Vallaris หรือ GISTDA) ลงในหน่วยความจำของระบบ
  * ฟังก์ชัน `openKeyModal()` / `closeKeyModal()`: สลับค่าสถานะ Boolean เปิด-ปิดหน้าต่างป๊อปัปกรอกข้อมูล API Key เมื่อระบบตรวจพบว่า User ส่งคำสั่งเรนเดอร์แผนที่แต่ยังไม่มีคีย์ผูกไว้ พร้อมระงับการทำงานกล่องแชทชั่วคราว
  * ฟังก์ชัน `setPendingChat()` / `clearPendingChat()`: บันทึกหรือล้างข้อความและรูปภาพชั่วคราวที่ค้างอยู่บน Chat Input สโตร์จะเก็บข้อความไว้และสั่งยิงหาหลังบ้านให้อัตโนมัติหลังจาก User กรอกคีย์เสร็จสิ้น
  * ฟังก์ชัน `setcurrentConversationApiKey(key)`: อัปเดตรหัส API Key ประจำบริบทห้องสนทนาปัจจุบันลงใน Store ล็อกสิทธิ์และโควตาของคีย์รหัสให้ตรงตามห้องแชทนั้น ๆ
  * ฟังก์ชัน `setSessionKey()` / `clearSessionKeys()`: บันทึกและจับคู่ความสัมพันธ์การผูก API Key กับ Conversation ID เรียกใช้โดยอัตโนมัติเมื่อ User คลิกสลับห้องแชทไปมาทางแผงควบคุมฝั่งซ้ายเพื่อดึงคีย์กลับมาใช้งาน
  * ฟังก์ชัน `triggerLayerMention(layerId)` / `clearPendingMention()`: แปลงไอดีเลเยอร์ให้อยู่ในรูปแบบโครงสร้างสตริงอ้างอิง `[layer_id: id]` พร้อมแนบเวลา Timestamp ส่งสัญญาณฝากข้อมูลข้ามโมดูลให้กล่องข้อความ `<ChatInput />` ดึงข้อความไปแทรกเป็นป้ายข้อความอ้างอิง (Mention Chip) ใน Text Editor อัตโนมัติ
  * ฟังก์ชัน `setPendingAttribute(text)` / `clearPendingAttribute()`: จัดเก็บข้อความคุณลักษณะ (Attribute Name) ที่ User คลิกเลือกจากตาราง Property บนแผนที่ ส่งข้อความไปแทรกต่อท้ายในกล่องข้อความแชททันที
  * ฟังก์ชัน `setActiveChatId(id)`: ปรับปรุงข้อมูลไอดีห้องสนทนาที่กำลังเปิดรันอยู่บนหน้าจอล่าสุดทุกครั้งที่มีการเปลี่ยนห้องแชท เพื่อทำการดึงประวัติการคุย คีย์ และการจัดการเลเยอร์ให้ถูกต้องตามห้องนั้น ๆ
  * ฟังก์ชัน `clearLayers()`: สั่งรีเซ็ตอาเรย์เลเยอร์แผนที่ อาเรย์เลเยอร์ซ่อน และออบเจกต์ประวัติสถิติเลเยอร์ให้กลับไปเป็นค่าว่างพร้อมกันทั้งหมดเมื่อต้องการล้างกราฟิกออกจากแผนที่
  * **การรักษาสถานะข้อมูล (State Persistence):** ครอบสโตร์ด้วย Middleware คำสั่ง `persist` จัดเก็บข้อมูลไว้ภายในหน่วยความจำ `sessionStorage` ของบราวเซอร์ (คีย์ชื่อ `'map-layer-counter-storage'`) ข้อมูลไม่สูญหายเมื่อรีเฟรชหน้าจอ (F5) แต่ล้างทิ้งเมื่อปิดแท็บ มีการเขียนฟังก์ชัน `partialize` เพื่อเลือกบันทึก**เฉพาะ** ตัวแปรออบเจกต์สถิติ `layerHistoryCount` เท่านั้นลงในแคช

## 📂 โครงสร้างย่อยภายใน src/features (Feature Blueprint)

> **พิมพ์เขียวมาตรฐาน:** ทุกโมดูลฟีเจอร์หลักภายใต้โฟลเดอร์ `src/features` (เช่น `auth`, `chat`, `map`) จะแยกโฟลเดอร์ย่อยตามหน้าที่อย่างเป็นเอกเทศดังนี้

* **โครงสร้างภายในของแต่ละฟีเจอร์:**
  * 📁 `components/`: จัดเก็บองค์ประกอบหน้าต่างและชิ้นส่วนอินเตอร์เฟส (UI Components) เฉพาะทางที่ใช้งานอยู่ภายในฟีเจอร์นั้น ๆ เท่านั้น
  * 📁 `config/`: ศูนย์กลางจัดเก็บไฟล์คอนฟิกูเรชัน ค่าคงที่ระบบ เส้นทาง API (Endpoints) และเงื่อนไขการตรวจสอบข้อมูลทั้งหมดของฟีเจอร์นั้น ๆ
  * 📁 `services/`: จัดเก็บลอจิกการประมวลผลหลัก (Business Logic) ทำหน้าที่เชื่อมต่อ API ภายนอกเพื่อรับส่ง หรือแปลงโครงสร้างข้อมูลก่อนส่งให้หน้าจอแสดงผล
  * 📁 `hooks/`: จัดเก็บ Custom Hooks สำหรับควบคุมสถานะ (State) การเปลี่ยนแปลงของข้อมูล (Side Effects) และลอจิกการทำงานแยกออกจากส่วน UI
  * 📁 `types/`: จัดเก็บประเภทข้อมูล (Types) และอินเตอร์เฟส (Interfaces) ที่ใช้งานภายในโมดูล เพื่อคุมมาตรฐาน Type Safety ของฟีเจอร์นั้น ๆ
  * 📄 `index.ts`: หน้ากากด่านหน้า (Public API / Barrel File) ทำหน้าที่ระบุและ Export เฉพาะคอมโพเนนต์ ฟังก์ชัน หรือ Hooks หลัก ๆ ที่อนุญาตให้โฟลเดอร์ภายนอกเรียกใช้งานได้ เพื่อลดความซับซ้อนของ Import Paths

### 📁 Config

#### 📄 auth.config.ts
> **หน้าที่หลัก:** ศูนย์รวมการตั้งค่าและกำหนดค่าคงที่ทั้งหมดของระบบยืนยันตัวตน (Auth) การจัดการ Token และเกณฑ์การตรวจสอบข้อมูลฟอร์มไว้ที่เดียว

* **กลไกสำคัญ:**
  * **มัดรวม Endpoints และตั้งค่า API:** กำหนดพิกัด Base URL และรวบรวมเส้นทาง (Paths) สำหรับยิงหลังบ้านทั้งหมด เช่น ล็อกอิน/รีเฟรช/ดึงเซสชัน (`/auth/sessions`), สมัครสมาชิก (`/auth/register`), สร้าง Guest (`/auth/guests`) รวมถึงแก๊งจัดการ API Keys
  * **กำหนดเวลาหมดอายุของ Token:** ตั้งเวลาหมดอายุของ Access Token (10 นาที), Refresh Token (7 วัน), เซสชันของ Guest (1 ชั่วโมง) พร้อมตั้งเวลาหน่วงสำหรับเริ่มโหลดตัวรีเฟรชล่วงหน้า
  * **จัดการชื่อคีย์เซสชันและที่เก็บข้อมูล:** ระบุชื่อคีย์สำหรับใช้อ้างอิงจัดเก็บลงหน่วยความจำบราวเซอร์และคุกกี้ (เช่น `access_token`, `refreshToken`, `user`) พร้อมตั้งรอบเวลาเช็ก Token ทุก 1 นาที 
  * **Validation:** ล็อกเงื่อนไขความปลอดภัยสำหรับใช้ตรวจเช็กตอนสมัครสมาชิก เช่น รหัสผ่านต้องยาวไม่ต่ำกว่า 8 ตัว (บังคับมีตัวพิมพ์ใหญ่และตัวเลข), ชื่อต้องยาวเกิน 3 ตัวขึ้นไป และมี Regex เช็กหน้าตาอีเมล
  * **ควบคุมทิศทางเปลี่ยนหน้าและเปิด/ปิดฟีเจอร์:** ระบุเส้นทางสำหรับนำทาง User ปลายทางหลังล็อกอิน/ล็อกเอาต์สำเร็จ พร้อมมีสวิตช์ Boolean สำหรับสั่งเปิด/ปิดระบบทำงานย่อยภายใน (เช่น การเปิดระบบรีเฟรชล่วงหน้า หรือการเปิดบันทึก Log)

### 📁 Context

#### 📄 AuthContext.tsx
> **หน้าที่หลัก:** ตัวจัดการสิทธิ์และการคงสถานะเข้าสู่ระบบ (Authentication State) ของแอปพลิเคชัน ทำหน้าที่คอยกระจายข้อมูลสถานะผู้ใช้งาน และ Token ไปให้ทุกคอมโพเนนต์รอบนอกดึงไปใช้งานร่วมกัน

* **กลไกสำคัญ:**
  * **ดึงเซสชันเก่ากลับมาตอนเปิดแอป:** มีระบบตรวจสอบเมื่อเริ่มต้นแอปพลิเคชันออโต้เพื่อเช็กกุญแจ Access Token และวันหมดอายุจากระบบคุกกี้ หากข้อมูลยังไม่หมดอายุจะดึงข้อมูลผู้ใช้จากคลัง `localStorage` มาตั้งค่าสเตตเปิดใช้งานระบบต่อทันที
  * **ระบบเช็กและต่ออายุ Token ล่วงหน้า:** มีการใช้ `setInterval` รันดักจับเวลาทุก ๆ 1 นาที คอยเช็กว่ารหัสเข้าใช้งานใกล้หมดอายุหรือยัง หากตรวจพบว่าใกล้หมดอายุ ระบบจะยิงคำสั่ง `refreshAccessToken` ไปต่ออายุหลังบ้านล่วงหน้าแบบเงียบ ๆ เพื่อป้องกันไม่ให้เซสชันของ User หลุดกลางคัน
  * **ฟังก์ชันล้างไพ่เคลียร์ข้อมูลค้างคา:** มีการใช้ `clearAuthState` สำหรับสั่งทำลายล้างสถานะในหน่วยความจำ สั่งทำลายคิวหน่วงเวลา `clearInterval`/`clearTimeout` ที่ค้างอยู่ทั้งหมด และล้างคุกกี้และข้อมูลประวัติในหน่วยความจำบราวเซอร์ออกจนหมดจดตอนสลับเซสชัน
  * **ส่งออก Custom Hook ให้เรียกใช้ง่าย:** เขียนฟังก์ชัน `useAuth` ครอบคำสั่งดึงบริบทเอาไว้ตอนท้ายไฟล์ เพื่อคอยดักแจ้งเตือนเมื่อลืมผูก Provider และช่วยให้คอมโพเนนต์รอบนอกสามารถดึงสถานะยูสเซอร์ไปใช้งานสั้น ๆ ได้ในบรรทัดเดียว

### 📁 Hooks

#### 📄 useApiKeys.ts
> **หน้าที่หลัก:** Custom Hook สำหรับจัดการข้อมูล API Keys (CRUD) และรายชื่อ Host ยืนยันสิทธิ์ในระบบทั้งหมด โดยเชื่อมต่อข้อมูลเซอร์วิสและอัปเดตสเตตให้คอมโพเนนต์นำไปใช้งานต่อ

* **กลไกสำคัญ:**
  * **โหลดข้อมูลคู่ขนานด้วย Promise.all:** ฟังก์ชัน `fetchInitialData` จะตรวจเช็กสิทธิ์ยูสเซอร์ และใช้ `Promise.all` เพื่อรันยิง API ดึงรายการคีย์ (`getKeys`) และรายชื่อโฮสต์สำหรับสร้างคีย์ (`getKeyHosts`) พร้อมกันคู่ขนานสองเส้นเพื่อลดเวลาในการโหลดหน้าเว็บ
  * **จัดการสเตตข้อมูลระบบ CRUD ครบวงจร:** มัดรวมฟังก์ชันควบคุมสถานะข้อมูล ได้แก่ `addKey` (ส่งข้อมูลสร้างคีย์และยัดต่อท้ายสเตตเดิม), `updateKey` (ส่งอัปเดตและใช้ `.map` ตรวจเช็กไอดีเพื่อเปลี่ยนข้อมูลรายการคีย์ในสเตต), และ `deleteKey` (ส่งลบคีย์และใช้ `.filter` คัดไอดีรายการนั้นออกจากสเตตทันที)
  * **ผูกลอจิกเรียกใช้ซ้ำปลอดภัย:** ใช้ `useCallback` ครอบฟังก์ชันดึงข้อมูลเริ่มต้นเพื่อล็อกหน่วยความจำไม่ให้ Re-render ซ้ำซ้อน และทำการรีเทิร์นส่งออกสเตตข้อมูลพร้อมเมธอดทำงานรวมถึงฟังก์ชัน `refetch` ให้หน้าจอภายนอกดึงไปใช้งานได้ทันที

### 📁 Services

#### 📄 apiKey.service.ts
> **หน้าที่หลัก:** เซอร์วิสจัดการข้อมูลเครือข่ายสำหรับระบบ API Keys (CRUD) ทำหน้าที่เป็นเลเยอร์เรียกใช้ `apiClient` เพื่อยิง Request ไปประมวลผลที่เซิร์ฟเวอร์หลังบ้านตาม Endpoints ที่กำหนดไว้ในคอนฟิก

* **กลไกสำคัญ:**
  * **จัดการข้อมูลคีย์ครบวงจร (CRUD):** มัดรวมเมธอดส่งคำสั่งเชื่อมต่อหลังบ้าน ได้แก่ `getKeys` (ยิง GET ดึงรายการคีย์ทั้งหมดมาโชว์), `createKey` (ยิง POST ส่งก้อนข้อมูลเพื่อสร้างคีย์ใหม่), `updateKey` (ยิง PUT อัปเดตแก้ไขข้อมูลคีย์รายตัวตามไอดี), และ `deleteKey` (ยิง DELETE สั่งลบคีย์ออกจากฐานข้อมูลถาวร)
  * **ดึงรายละเอียดคีย์ตัวเต็ม:** มีเมธอด `getKeyById` สำหรับยิง GET เจาะจงไอดีเพื่อขอข้อมูลรายละเอียดคีย์ รวมถึงรหัสคีย์จริงตัวเต็มแบบไม่ซ่อนหน้ากาก เพื่อนำไปใช้ส่งต่อให้คอมโพเนนต์หน้าจอมอดอลเปิดแสดงผลให้คัดลอก
  * **ดึงรายชื่อโฮสต์ของระบบ:** มีเมธอด `getKeyHosts` สำหรับยิง GET เพื่อดึงรายการข้อมูลกลุ่มโฮสต์ที่ระบบอนุญาตมาเตรียมไว้ให้ผู้ใช้เลือกผูกตอนสร้างรหัส API Key ชุดใหม่

#### 📄 auth.service.ts
> **หน้าที่หลัก:** อินสแตนซ์ Axios และคลังฟังก์ชันสำหรับควบคุม API ยืนยันตัวตน (Authentication) จัดการวงจรชีวิตของ Token ทั้งในหน่วยความจำ คุกกี้ และ LocalStorage รวมถึงทำระบบป้องกันตั๋วหลุดด้วยระบบ Auto-Refresh ผ่าน Interceptors

* **กลไกสำคัญ:**
  * **ระบบคิวรีเฟรชตั๋วอัตโนมัติอัจฉริยะ (Axios Interceptors):** มีการใช้ Request Interceptor คอยแนบ Token ไปกับ Headers ทุกครั้ง และฝัง Response Interceptor คอยดักจับรหัส 401 (token expired) หากตรวจพบระบบจะทำการล็อกคิว (`isRefreshing = true`) และจับ Request ตัวอื่น ๆ ที่ยิงเข้ามาพร้อมกันเข้าคิวรอ (`refreshSubscribers`) จากนั้นจะยิงขอต๋วใหม่มาอัปเดตและปล่อยทุก Request ให้วิ่งต่อออโต้โดยที่ผู้ใช้ไม่รู้สึกว่าระบบหลุด (Silent Refresh)
  * **จัดการเซสชันและคำนวณเวลาหมดอายุแยกเคส:** ฟังก์ชัน `saveAuthSession` และ `clearAuthSession` ทำหน้าที่คุมจังหวะบันทึกและล้างข้อมูลเซสชันในระบบ โดยระบบจะคำนวณเวลาหมดอายุแยกตามประเภทสิทธิ์ (เช่น แขกหมดอายุภายใน 1 ชั่วโมง, สมาชิกทั่วไป Access Token อยู่ได้ 10 นาที และ Refresh Token อยู่ได้ 7 วัน)
  * **โอนย้ายข้อมูลจาก Guest เป็น Member เต็มตัว:** ในเมธอด `login` และ `register` จะมีการดักเช็กคุกกี้ `guest_id` หากพบว่าผู้ใช้เคยใช้งานในโหมดแขกมาก่อน จะทำการแนบไอดีแขกพ่วงไปใน Payload ส่งให้หลังบ้าน เพื่อให้เซิร์ฟเวอร์ย้ายประวัติข้อมูลเก่า (เช่น ประวัติการแชท) มาผูกเข้ากับบัญชีสมาชิกใหม่ได้ทันที
  * **ตัวแกะกล่องคัดกรอง Error หลังบ้าน (Error Normalizer):** ฟังก์ชัน `createApiError` ทำหน้าที่คัดแยกรูปแบบ Error ที่ส่งกลับมาจากเซิร์ฟเวอร์ ไม่ว่าจะส่งมาเป็นข้อความธรรมดา, โครงสร้าง Object ชั้นลึก หรืออาเรย์ข้อผิดพลาด ย่อยข้อมูลให้เหลือเพียงข้อความชุดเดียวที่พร้อมส่งต่อให้ฝั่งหน้าจอไปพ่นแสดงผลได้ทันที

### 📁 Utils

#### 📄 guest-timer.util.ts
> **หน้าที่หลัก:** ฟังก์ชันช่วย (Utility Functions) สำหรับคำนวณเวลา, ตั้งเวลา Polling ตรวจสอบหมดอายุ และสั่งทำความสะอาดข้อมูลของ Guest Session

  * **isGuestTimeUp:** ดึงเวลาหมดอายุจาก Cookie มาแปลงตัวเลขเพื่อเทียบกับ `Date.now()` และเช็กสถานะเงื่อนไขเพื่อสรุปว่า Session ของ Guest หมดเวลาแล้วหรือยัง
  * **startGuestExpiryTimer:** รันระบบเช็กเวลาหมดอายุของ guest user ทันทีหนึ่งครั้งและตั้งลูป Polling ด้วย `setInterval` ทุก ๆ 5 วินาที หากเวลาหมดจะยิง `onExpired` Callback ออกไปทันที พร้อม Return ฟังก์ชันล้าง `clearInterval` เพื่อป้องกันปัญหา Memory Leak
  * **checkAndCleanupExpiredGuest:** คอยดักเช็กสถานะขยะตกค้าง ถ้าพบเคสที่ Access Token ใน Cookie ถูกลบหายไปแล้ว แต่ยังมี `guestStartTime` ฝังค้างอยู่ใน `localStorage` ระบบจะทำลายคีย์ตัวนั้นทิ้งทันทีเพื่อเคลียร์พื้นที่แอป

#### 📄 index.ts (Root)
> **หน้าที่หลัก:** ทำหน้าที่เป็น Barrel File (จุดส่งออกหลักประจำโมดูล) คอยทำ Re-export รวบรวมของสำคัญภายในโมดูล Auth ทั้งหมดออกไปข้างนอก เพื่อให้ฟีเจอร์อื่นเปิดจุดท่อ Import ได้จากที่นี่ที่เดียว (Public API Gateway)

* **จุดเด่นสำคัญ (Key Highlights):**
  * **Clean Architecture & Import Path:** ยุบรวมช่องทางการเรียกใช้จากโฟลเดอร์ย่อย (Context, Services, Types, Config) มารวมไว้ที่จุดศูนย์กลาง ทำให้เวลาโมดูลภายนอกต้องการเรียกใช้งาน สามารถจิ้มมาที่ `@/features/auth` ได้สั้น ๆ สายโค้ดดูคลีนและเป็นระเบียบขึ้นมาก
  * **Encapsulation Control:** ช่วยคัดกรองและเปิดเผยเฉพาะสิ่งที่จำเป็นให้ระบบรอบนอกมองเห็น ส่วนไฟล์ลอจิกเฉพาะกิจที่ใช้กันเองภายในโมดูล (เช่น โฟลเดอร์ `utils` หรือคอมโพเนนต์ย่อยบางตัว) จะถูกซ่อนไว้ข้างหลังอย่างเป็นสัดส่วน ป้องกันไม่ให้ Dev คนอื่นเรียกใช้ข้ามสายจนโครงสร้างระบบเละ

### 📁 Components

#### 📄 ChatInput.tsx
> **หน้าที่หลัก:** กล่องรับข้อความสั่งงาน AI โดยใช้ Rich Text Editor (Tiptap) ทำระบบ `@mention` ดึงรายชื่อ Layer บนแผนที่ พร้อมรองรับการแนบไฟล์ภาพ และดักรับค่าจากหน้าจอแผนที่ (attribute name or value) มาฉีดเป็นข้อความในแชทโดยอัตโนมัติ

* **กลไกสำคัญ:**
  * **การจัดการข้อความ Rich Text และระบบ @mention:** ใช้ Tiptap Editor คู่กับ `Mention Extension` คุมพวกป้ายแท็กในช่องพิมพ์ตอนกด `@` และมีฟังก์ชัน `getSerializedContent` คอยแกะโครงสร้าง JSON ของ Editor แปลงกลับเป็น String ดิบส่งไปให้ API หลังบ้าน
  * **ซิงก์ข้อมูลแผนที่กับ Zustand Store:** ใช้ `useEffect` ดักจับค่า `pendingMention` และ `pendingAttribute` จาก `useMapStore` เมื่อยิงเหตุการณ์คลิก Layer หรือตารางบนแผนที่ ระบบจะดึงข้อมูลมาฉีดเข้ากล่องพิมพ์ พร้อมโฟกัส Cursor ไปท้ายประโยคให้ทันที
  * **การวางรูปภาพจาก Clipboard และแปลงไฟล์:** รองรับการอัปโหลดและกดวางภาพ (`onPaste`) มีระบบเช็กจำกัดจำนวนและขนาดไฟล์สูงสุด (`MAX_FILE_SIZE`) ตามค่าใน `CHAT_CONFIG` ก่อนจับแปลงเป็น Base64 String เพื่อเตรียมจัดส่ง
  * **ระบบแนะนำ Prompt:** ฟังก์ชัน `handleSuggestionClick` คอยดักการคลิกปุ่มคีย์ลัดหัวกล่อง เพื่อฉีดข้อความสำเร็จรูป (เช่น ล้างชั้นข้อมูล หรือเปลี่ยนสีตามแอตทริบิวต์) และสั่งพิมพ์ `@` อัตโนมัติเพื่อเปิดป๊อปอัพค้นหา Layer ต่อได้ทันที
  * **ควบคุมสถานะกล่องพิมพ์ และป้ายเตือนตามบริบท:** สั่งล็อกการแก้ไข (`setEditable`) อัตโนมัติเมื่อ `guest id` หมดเวลา หรือระบบรอผูก API Key พร้อมสแกน Keyword ในกล่องเพื่อเปิดแสดงแถบป้ายแนะนำเทคนิค (Tip Banner) ให้แมตช์ตามสถานการณ์

#### 📄 Header.tsx
> **หน้าที่หลัก:** ส่วนหัวของหน้าจอแชท (Chat Header) ทำหน้าที่แสดงผลและควบคุมการสลับเปลี่ยนโมเดล AI (Ollama Models) ที่ใช้ในการประมวลผลคำสั่ง พร้อมรองรับการเปิด/ปิดสิทธิ์การเลือก model

* **กลไกสำคัญ:**
  * **ค้นหาและแสดงผลชื่อโมเดลปัจจุบัน:** ใช้ฟังก์ชัน `.find()` ค้นหา Object โมเดลจากอาเรย์ `models` ที่ส่งผ่าน props มาตามไอดี `selectedModel` เพื่อดึงชื่อจริงและขนาดโมเดลมาโชว์ พร้อมระบบแสดงข้อความ "Loading models..." แบบอัตโนมัติหากอาเรย์ยังว่างเปล่า
  * **ทำ Custom Dropdown ด้วย Native Select:** ใช้เทคนิคซ้อนแท็ก `<select>` จริงไว้ด้านบนแล้วสั่งลบความโปร่งแสงเป็น `opacity-0` เพื่อใช้ UI กล่องปุ่มที่แต่งเองจาก Tailwind CSS ในการโชว์หน้าตา แต่ยังได้หน้าต่างเลือกโมเดล (Native Picker) ที่เสถียรและลื่นไหลของระบบปฏิบัติการ
  * **ล็อกการใช้งานตามสถานะ:** ใช้สถานะ `isModelDisabled` คุมกลไกฝั่ง UI โดยหากโดนสั่งล็อก ระบบจะปิดการทำงานตัวเลือกทันที เปลี่ยนร่างเมาส์เป็นรูปห้ามกด พ่นสไตล์ความจาง (`opacity-50`) และสั่งซ่อนไอคอนลูกศร `ChevronDown` เพื่อป้องกันผู้ใช้กดเปลี่ยนโมเดลระหว่างรันคำสั่งค้างอยู่

#### 📄 MentionList.tsx
> **หน้าที่หลัก:** ป๊อปอัพแสดงรายชื่อ Layer บนแผนที่ (Suggestion Dropdown) ที่จะเด้งขึ้นมาตอนที่ผู้ใช้พิมพ์สัญลักษณ์ `@` ในช่องแชท เพื่อให้กดเลือกแท็ก Layer ผูกเข้าไปในชุดข้อความสั่งงาน

* **กลไกสำคัญ:**
  * **ควบคุมการเลือกผ่านคีย์บอร์ดจากระยะไกล:** ใช้ `useImperativeHandle` ผูกเมธอด `onKeyDown` เพื่อเปิดช่องให้ Tiptap Editor ส่ง Event คีย์บอร์ดข้ามมาสั่งงานได้ โดยดักจับปุ่ม `ArrowUp` / `ArrowDown` เพื่อเลื่อนตำแหน่งไฮไลต์ และกด `Enter` เพื่อยืนยันเลือกรายการโดยไม่ต้องละมือจากแป้นพิมพ์
  * **ส่งคำสั่งแปลงข้อความเป็นป้ายแท็ก:** มีฟังก์ชัน `selectItem` คอยดักจับไอเทมที่เลือก ดึงค่า `id` และ `title` ของ Layer ชุดนั้นส่งกลับไปให้ฟังก์ชัน `command` ของ Tiptap เพื่อแปลงร่างข้อความธรรมดาให้กลายเป็น Token Chip ในกล่องแชท
  * **รีเซ็ตตำแหน่งไฮไลต์อัตโนมัติ:** ใช้ `useEffect` คอยตรวจเช็กอาเรย์ `items` เมื่อรายชื่อ Layer มีความเปลี่ยนแปลงจากการพิมพ์ฟิลเตอร์ค้นหา ระบบจะดีดสถานะ `selectedIndex` กลับไปเริ่มนับ 0 ใหม่ทันที เพื่อป้องกันปัญหาดัชนีไฮไลต์ค้างเกินขอบอาเรย์ปัจจุบัน
  * **ซิงก์ตำแหน่งร่วมกับเมาส์:** มีการผูก Event `onMouseEnter` เข้ากับรายการปุ่มช้อยส์เลือก ทำให้ผู้ใช้สามารถสลับไปใช้เมาส์เลื่อนผ่านเพื่ออัปเดตสเตต `selectedIndex` สลับกับคีย์บอร์ดได้แบบ Real-time ไม่มีเอ๋อ

#### 📄 MessageItem.tsx
> **หน้าที่หลัก:** แสดงผลกล่องข้อความแชทแต่ละรายการ (แยกฝั่ง User และ Bot AI) ควบคุมระบบแก้ไขข้อความเดิม, แสดงผลรูปภาพแนบ, ขั้นตอนการคิดของ AI, รวมถึงแผงควบคุมพิเศษ เช่น ช่องพิมพ์ค้นหาเลเยอร์ และปุ่มกดเลือกเลเยอร์แผนที่พร้อมระบบแบ่งหน้า

* **กลไกสำคัญ:**
  * **สแกนและแปลงไอดีให้เป็นป้ายเลเยอร์อ่านง่าย:** ฟังก์ชัน `renderFormattedContent` ใช้ Regex ดักจับรหัสไอดี 24 หลักในเนื้อหาข้อความ แล้ววิ่งไปหาข้อมูลเลเยอร์จริงใน Zustand Store (`dynamicLayers`) ถ้าเจอจะเปลี่ยนจากไอดีดิบเป็นป้ายชื่อตัวหนา (Chip tag) ที่ตรงกับสไตล์สีของฝั่งนั้น ๆ ทันที
  * **แผงค้นหาและกดเลือกเลเยอร์แบบอินเตอร์แอคทีฟ:** สำหรับข้อความฝั่ง Bot ที่เป็นรายการเลเยอร์ ระบบจะเปิดช่องอินพุตให้ผู้ใช้พิมพ์ค้นหา (`onSendSearch`) และมีระบบปุ่มเปิดสลับหน้าเลเยอร์ (Pagination) พร้อมคำนวณตัวเลขรายการสรุป โดยระบบจะล็อกปุ่มและช่องพิมพ์ทั้งหมดทันทีหากไม่ใช่ข้อความล่าสุด หรือผู้ใช้เลือกคำตอบไปแล้ว
  * **ตรวจสอบสิทธิ์การแก้ไขข้อความย้อนหลัง:** รองรับการคลิกปุ่ม Pencil เพื่อสลับข้อความผู้ใช้ไปเป็นกล่อง `<Textarea>` สำหรับส่งแก้ไขคำถามเดิม โดยใช้สเตตตรวจสอบจาก `useAuth` หากพบว่าเป็น `guest id` ระบบจะล็อกปุ่มถาวรและเปิดแสดง Tooltip เตือนให้ล็อกอินก่อนใช้งาน
  * **แสดงลูปความคิด AI และระบบจัดคิวเลื่อนหน้าจอตามรูปภาพ:** ตรวจเช็กค่า `msg.thinking` เพื่อแยกแสดงบล็อกขั้นตอนการประมวลผล (Chain of Thought) ของโมดูล และจัดการพ่นรูปภาพแนบจากอาเรย์หรือ URL ประวัติเก่า โดยฝังคำสั่งดีดหน้าจอลงล่างสุด (`scrollToBottom`) ใน Event `onLoad` ของรูปภาพ เพื่อป้องกันหน้าจอกระตุกตอนภาพโหลดเสร็จ

#### 📄 MessageList.tsx
> **หน้าที่หลัก:** บอร์ดแสดงรายการข้อความแชททั้งหมด คอยคุมหน้าจอตอนไม่มีข้อความ (Empty State) พร้อมจัดการลอจิกตำแหน่งการเลื่อนหน้าจอ (Scroll Positioning) ระดับสูง ทั้งจังหวะที่โหลดประวัติแชทย้อนหลัง (Infinite Scroll) และจังหวะที่ข้อความ AI กำลังสตรีมมิ่งไหลออกมา

* **กลไกสำคัญ:**
  * **ระบบคำนวณชดเชยระยะ Scroll ตอนดึงประวัติเก่า:** ใช้ `useLayoutEffect` คอยจำค่า `scrollHeight` และ `scrollTop` ก่อนที่ก้อนข้อมูลชุดเก่าจะโหลดเสร็จ เมื่อประวัติแชทไหลเข้ามาเติมด้านบน ระบบจะคำนวณส่วนต่างความสูงและชดเชยตำแหน่งจุดเดิมให้ผู้ใช้ทันที จอเลยไม่เด้งหลุดกระตุกตอนโหลดประวัติย้อนหลัง
  * **เช็กพฤเทิกรรมผู้ใช้เพื่อระงับ Auto-Scroll:** ฟังก์ชัน `handleScroll` คอยคำนวณระยะห่างจากขอบล่างสุด (`distanceFromBottom`) ถ้าผู้ใช้ตั้งใจเลื่อนจอขึ้นไปอ่านข้อความเก่าเกิน 50px ระบบจะตั้งค่า `isUserScrolledUp = true` เพื่อหยุดการสั่งเลื่อนหน้าจอลงล่างอัตโนมัติ ป้องกันแอปดีดเมาส์สู้กับมือผู้ใช้
  * **ล็อกหน้าจอลงล่างสุดตามข้อความสตรีมมิ่งด้วย ResizeObserver:** มีการผูก `ResizeObserver` ตรวจจับขนาดกล่อง Wrapper หลัก เมื่อข้อความจาก AI ค่อย ๆ งอกยาวขึ้น (Streaming Response) และผู้ใช้ไม่ได้เลื่อนจอขึ้นไปค้างไว้ ระบบจะสั่ง `scrollToBottom("instant")` ล็อกหน้าจอให้เลื่อนลงตามตัวหนังสือแบบ Real-time ทันที
  * **ระบบตรวจจับขอบบน (Infinite Scroll) และหาข้อความล่าสุด:** มีการดักจับสเตต scroll หากตัวขยับแตะขอบบนสุดจะทริกเกอร์เรียกฟังก์ชัน `onLoadMore` เพื่อไปดึงข้อมูลประวัติแชทชุดถัดไปจากฐานข้อมูล พร้อมทำลูปรันย้อนกลับเพื่อระบุตำแหน่งข้อความผู้ใช้ล่าสุดสำหรับส่งสิทธิ์ส่งแก้ไข (`canEdit`) ให้ถูกตัว

#### 📄 Sidebar.tsx
> **หน้าที่หลัก:** แถบเมนูด้านข้าง (Sidebar) สำหรับบริหารจัดการรายการห้องแชท รองรับการพับเก็บ-กางออก, สร้างแชทใหม่, เปลี่ยนชื่อ, ลบห้องแชท พร้อมระบบโหลดประวัติแชทหน้าถัดไปอัตโนมัติเมื่อเลื่อนสกรอลล์ และระบบบล็อกสิทธิ์ผู้ใช้งานที่เป็น Guest

* **กลไกสำคัญ:**
  * **โหลดประวัติแชทหน้าถัดไปอัตโนมัติ (Infinite Scroll):** ใช้ Hook `useInView` ดักจับ Element ล่องหน ที่แปะไว้ใต้ลิสต์แชททั้งหมด เมื่อผู้ใช้สกรอลล์มาเห็นติ่งล่างสุด ระบบจะเรียกฟังก์ชัน `fetchNextSidebarPage()` เพื่อไปดึงแชทเก่าหน้าถัดไปมาเติมทันที โดยใช้ `isInitialMount` คอยดักไม่ให้ระบบแอบยิง API ตั้งแต่โหลดหน้าจอครั้งแรก
  * **สกัดขาและบล็อกสิทธิ์โหมด Guest ด้วย Dialog:** ดักเช็กสถานะผู้ใช้ผ่าน `useAuth` หากพบว่าเป็น Guest (`isGuest`) แล้วพยายามจะกดปุ่ม New Chat หรือคลิกสลับห้องแชท ระบบจะระงับคำสั่งเดิมแล้วสั่งเปิดก้อนมอดอล `<Dialog>` แจ้งเตือนข้อจำกัดเพื่อนำทางผู้ใช้ไปหน้า `/login` ทันที รวมถึงใช้ Tailwind ซ่อนปุ่มแก้ไขและปุ่มลบแชทถาวร
  * **เปลี่ยนชื่อห้องแชทแบบ Inline:** ใช้สเตต `editingId` คุมจังหวะสลับข้อความชื่อแชทไปเป็นช่อง `<input>` ให้พิมพ์แก้ไขได้ทันที โดยฝังคำสั่ง `e.stopPropagation()` ดักไว้ทุกปุ่มควบคุม (Check, X, Pencil, Trash) เพื่อป้องกันไม่ให้สเตตคลิกฟังก์ชันมันซ้อนกันจนกลายเป็นกดเปิดห้องแชทโดยไม่ตั้งใจ
  * **ระงับการทำงานเมื่อระบบรอผูก API Key:** มีการเช็กสเตต `isKeyModalOpen` หากหน้าจอกำลังบังคับให้ผูกรหัส API Key อยู่ แถบ Sidebar จะทำการ Disabled ปุ่ม New Chat และล็อกรายชื่อแชททั้งหมดทันที พร้อมพ่นสไตล์สีเทา (`grayscale opacity-50`) เพื่อกดดันให้ผู้ใช้เคลียร์เรื่องผูกคีย์ที่ Popover หัวเว็บให้จบก่อน

#### 📄 suggestion.ts
> **หน้าที่หลัก:** ออบเจกต์ตั้งค่าระบบแนะนำ (Suggestion Configuration) ของ Tiptap Editor คอยดักจับคีย์เวิร์ดหลังจากที่ผู้ใช้พิมพ์สัญลักษณ์ `@` เพื่อดึงข้อมูลชั้นข้อมูลแผนที่ (Layer) มากรองค้นหา และควบคุมการแสดงผลของกล่องป๊อปอัพเมนูบนหน้าจอผ่านไลบรารี Tippy.js

* **กลไกสำคัญ:**
  * **ดึงและกรองรายชื่อ Layer นอก React Context:** เมธอด `items` ทำการดึงข้อมูล `dynamicLayers` จาก Zustand Store ตรง ๆ ผ่านคำสั่ง `.getState()` (เนื่องจากจุดนี้ไม่ใช่ React Component จึงใช้ Hook ไม่ได้) จากนั้นทำการกรองข้อความค้นหาแบบไม่สนใจตัวพิมพ์เล็ก-ใหญ่ และล็อกจำกัดผลลัพธ์ให้แสดงผลสูงสุดเพียง 5 รายการ
  * **สร้างและจัดพิกัดกล่องป๊อปอัพลอยบนหน้าเว็บ:** เมธอด `onStart` ทำหน้าที่แปลง React Component (`MentionList`) ให้กลายเป็นโครงสร้าง HTML DOM ผ่าน `ReactRenderer` แล้วส่งต่อให้ Tippy.js นำไปพ่นเปิดแสดงผลบนหน้าต่างเว็บ โดยใช้ค่า `props.clientRect` คอยคำนวณตำแหน่งพิกเซลให้กล่องเด้งขึ้นตรงกับพิกัด Cursor เสมอ
  * **อัปเดตพิกัดตามระยะพิมพ์:** เมธอด `onUpdate` จะคอยส่งต่อ Props ชุดใหม่ไปอัปเดตหน้าตาคอมโพเนนต์ลูกเมื่อผู้ใช้พิมพ์ตัวอักษรเพิ่ม พร้อมสั่งให้กล่อง Tippy ย้ายตำแหน่งพิกัดลอยตามระยะบรรทัดขยับขึ้นลงแบบ Real-time เพื่อป้องกันปัญหาป๊อปอัพหลุดตำแหน่งหน้าจอ
  * **จัดการปุ่มคีย์บอร์ดและล้างหน่วยความจำค้างคา:** เมธอด `onKeyDown` คอยดักปุ่ม `Escape` เพื่อสั่งปิดกล่องป๊อปอัพทันที ส่วนปุ่มลูกศรและปุ่ม Enter จะทำการส่งต่อ (Forward Event) ไปให้ลอจิกคีย์บอร์ดในไฟล์ `MentionList` ควบคุมต่อ พร้อมมีเมธอด `onExit` คอยสั่ง `.destroy()` ทำลายอินสแตนซ์ทิ้งทั้งหมดเพื่อป้องกันปัญหา Memory Leak

### 📁 Config

#### 📄 chat.config.ts
> **หน้าที่หลัก:** ศูนย์รวมการตั้งค่าและค่าคงที่ทั้งหมดของระบบแชท (Chat Feature) คุมสถาปัตยกรรมเครือข่าย, API Endpoints, ข้อจำกัดของฟอร์ม, Feature Flags ไปจนถึงชุดคีย์อินสแตนซ์ Event สำหรับใช้ซิงก์ข้อมูลคุยร่วมกับหน้าจอแผนที่

* **โครงสร้างคอนฟิกหลัก:**
  * **API & Endpoints:** กำหนด Base URL และ Headers พิเศษ (รองรับการทะลวง Ngrok สำหรับทดสอบระบบ) พร้อมรวบรวมเส้นทางยิง API แชท เช่น การดึงประวัติห้องแชท (`conversations`), ข้อความ (`messages`), รายชื่อโมเดล AI (`models`) และโมดูลวิเคราะห์ข้อมูล (`analytics`)
  * **Chat Settings & Validation:** ล็อกเกณฑ์จำกัดความปลอดภัยของช่องแชท คุมความยาวข้อความสูงสุด 2,000 ตัวอักษร, ลิมิตการแนบรูปภาพได้สูงสุด 1 รูป และจำกัดขนาดภาพห้ามเกิน 1 MB (`limitImgSizeMB`)
  * **Feature Flags & Pagination:** บอร์ดสวิตช์ Boolean สำหรับสั่งเปิด-ปิดการทำงานหลังบ้าน (เช่น ระบบบันทึก Chat Log, ระบบสตรีมมิ่งคำตอบ AI และระบบ Auto-Scroll หน้าจอ) พร้อมล็อกขนาดดึงประวัติแชทชุดละ 5 ข้อความ (`pageSize`)
  * **Map Events & Clear Modes:** คลังรหัสชื่อประเภทชุดคำสั่ง (Event Constants) สำหรับคุมการเปลี่ยนแปลงบนเลเยอร์แผนที่ เช่น สั่งล้างชั้นข้อมูล (`map_clear`), อัปเดตสไตล์สีลวดลาย (`map_style_patch`) และฟิลเตอร์ข้อมูลแอตทริบิวต์ (`map_filter_patch`) เพื่อให้ฝั่ง UI และเอนจินแผนที่สื่อสารตรงกันแบบไม่มีคำสะกดผิด

### 📁 Hooks

#### 📄 useChat.ts
> **หน้าที่หลัก:** Custom Hook ศูนย์กลางจัดการวงจรชีวิตของแชท (Chat Lifecycle), โหลดประวัติข้อความและรายชื่อห้องแชทย้อนหลัง, บริหารจัดการห้องแชท (CRUD), ควบคุมอายุการใช้งานเซสชันของ Guest และสร้างระบบเชื่อมต่อคำสั่งข้ามโมดูลไปยังระบบแผนที่

* **กลไกสำคัญ:**
  * **การแปลงโครงสร้างข้อมูล:** ฟังก์ชัน `mapBackendMessage` และ `mapBackendLayers` แปลงข้อมูล JSON ดิบจากหลังบ้านให้เป็นรูปแบบมาตรฐานของหน้าบ้าน เช่น จัดการ Event `map_options` ให้เข้ากับโครงสร้าง UI, ตรวจสอบและแยกค่ายผู้ให้บริการชั้นข้อมูล (Provider) ระหว่าง Vallaris กับ GISTDA และดึงลิงก์รูปภาพแนบมาใช้งาน
  * **ซิงก์สถานะกับ Zustand Store:** เชื่อมต่อกับ Store ส่วนกลางเพื่อกระจายค่า API Key ประจำเซสชัน, อัปเดตรายชื่อเลเยอร์ปัจจุบัน (`dynamicLayers`), พักข้อความค้างไว้กรณีรอคีย์ และควบคุมการเปิดกล่องป๊อปอัพ เรียกขอคีย์จากระยะไกล
  * **ระบบส่งข้อความซ้ำอัตโนมัติ (Silent Retry):** ดักจับความเปลี่ยนแปลงของ API Key เมื่อกรอกคีย์ใหม่สำเร็จหรือสลับห้องแชทที่มีคีย์ผูกอยู่ ระบบจะดึงข้อความที่ค้างอยู่ในคิว (`pendingChat`) สั่งยิงส่งซ้ำไปหาหลังบ้านให้ทันทีโดยอัตโนมัติ
  * **โหลดรายการแชทลง Sidebar:** โดยอัตโนมัติเมื่อเริ่มต้นระบบ โดยดึงรายชื่อห้องแชทล่าสุด คัดกรองห้องที่ถูกลบ จัดเรียงตามเวลาอัปเดต (`sortChats`) และเลือกเปิดห้องแชทล่าสุดให้ผู้ใช้หรือ Guest ทันทีตามสิทธิ์
  * **โหลดรายละเอียดและประวัติแชท:** ดึงข้อความในห้องแชทมาแปลงรูปแบบ, นำรหัส API Key เดิมในประวัติไปตั้งค่าเปิดสิทธิ์, เรียกคืนสถานะเลเยอร์บนหน้าจอแผนที่ และสร้างเซสชันจำลองรองรับโหมด Guest กรณีที่เป็นห้องคุยใหม่
  * **ระบบ Infinite Scroll แบบสองฝั่ง:** แยกท่อโหลดข้อมูลหน้าถัดไปเป็น 2 ฝั่งอิสระ ได้แก่ `fetchNextPage` ดึงข้อความเก่ามาต่อเติมด้านบนแชท และ `fetchNextSidebarPage` ดึงห้องแชทเก่ามาเพิ่มด้านล่างของ Sidebar โดยมีระบบตรวจสอบ ID ป้องกันข้อมูลซ้ำ
  * **จัดการห้องแชท (CRUD) แบบ Optimistic UI:** รวมฟังก์ชันควบคุมห้องแชท ได้แก่ `createNewChat` (ล้างคีย์และรีเซ็ตแผนที่), `deleteChat` (ลบห้องแชทและสลับไปห้องถัดไป) และ `renameChat` (เปลี่ยนชื่อบนหน้าจอทันทีแบบ Optimistic และย้อนกลับ (Rollback) หากการเชื่อมต่อเครือข่ายล้มเหลว)
  * **ระบบแก้ไขและส่งข้อความซ้ำ (Edit & Resend):** ฟังก์ชัน `editAndResend` จัดการจังหวะที่ผู้ใช้แก้ไขคำถามเก่า โดยระบบจะตัดบทสนทนาตั้งแต่ข้อความที่แก้ไขลงไปทิ้งทั้งหมด, เปลี่ยนไอดีข้อความนั้นเป็นไอดีชั่วคราว (`temp_edit_...`) และส่งคำสั่งไปสร้างคำตอบใหม่จาก AI ทันที
  * **ตรวจสอบอายุเซสชัน Guest (Polling):** รันระบบตรวจสอบร่วมกับ `startGuestExpiryTimer` ทุก ๆ 5 วินาที หากเซสชันหมดอายุ ระบบจะลบ Cookie, ล้างข้อความแชทบนหน้าจอ และเปิดป๊อปอัพแจ้งเตือนล็อกสิทธิ์ทันทีเพื่อความปลอดภัย
  * **ท่อส่งคำสั่งจากแผนที่ (Map Undo Integration):** ใช้ `latestPropsRef` ล็อกฟังก์ชันส่งข้อความและโมเดล AI ล่าสุดไว้ในหน่วยความจำ แล้วฝังฟังก์ชัน `triggerLayerUndo` ไว้ที่ Zustand Store ทำให้ปุ่มย้อนกลับ (Undo) บนแผนที่ สามารถสั่งลบชั้นข้อมูลผ่านระบบแชทได้โดยตรงแบบเงียบ ๆ

#### 📄 useChatStream.ts
> **หน้าที่หลัก:** Custom Hook สำหรับจัดการระบบรับส่งข้อความแชท AI และชุดคำสั่งควบคุมแผนที่แบบ Real-time Streaming (ผ่าน Server-Sent Events - SSE) โดยทําหน้าที่แกะและแปลง Binary Chunks เป็นสตริงข้อความ พร้อมทั้งดักจับกราฟิกพิกัดเชิงพื้นที่ยิงตรงไปอัปเดต Zustand Store เพื่อเปลี่ยนสไตล์และชั้นข้อมูลบนแผนที่ทันทีแบบเรียลไทม์

* **กลไกสำคัญ:**
  * **จัดการเซสชันและจับคู่ไอดี (Session & ID Swap):** รองรับระบบแยกสิทธิ์ระหว่างผู้ใช้และ Guest โดยจังหวะเปิดห้องแชทใหม่หน้าบ้านจะชิงสร้างไอดีชั่วคราว (`session_...`) ขึ้นมาล็อกตำแหน่งกล่องแชทแบบ Optimistic UI ทันที และเมื่อข้อมูลเริ่มไหลมาและหลังบ้านส่งไอดีจริงกลับมา (`conversationId`) ระบบจะสั่งรันลูปเปลี่ยนไอดีทุกจุดทั่วทั้งแอปให้กลายเป็นตัวจริงทันที
  * **ระบบหยุดรอคีย์ดักหน้าแอป (Missing API Key Guard):** ในระหว่างที่บอตกำลังสตรีมคำตอบ หากตรวจพบเงื่อนไขสิทธิ์ขาดส่ง API Key สำหรับเรนเดอร์แผนที่ (`needsApiKey`) ระบบจะทำการพักคิวแชทก้อนนี้ลงหน่วยความจำชั่วคราว (`setPendingChat`), สั่งยกเลิกท่ออ่านข้อมูล (`reader.cancel()`) และเรียกเปิดป๊อปอัพ Modal บังคับยูสเซอร์กรอกคีย์ทันทีเพื่อไม่ให้ระบบแครช
  * **ลงทะเบียนชั้นข้อมูลเชิงพื้นที่แบบไดนามิก (Layer Catalog):** ดักจับ Event `layerCatalog` เพื่อแกะพิกัดขอบเขต `bounds`, ช่วงซูม `min/maxzoom` และ URL ดิบของเลเยอร์ใหม่ พร้อมระบบสแกนตรวจสอบคำซ้ำ หากพบว่าเป็นเลเยอร์ใหม่จะสั่งลงทะเบียนเก็บเข้า Store ทันที แต่ถ้าเป็นเลเยอร์เดิมที่มีอยู่แล้วแต่เปลี่ยนชนิดโครงสร้าง (Type) ระบบจะสั่งทำการอัปเดต Patch ทับรายการเดิม
  * **คำนวณสถิติประวัติเลเยอร์ (Layer History Counter):** คอยตรวจเช็กจังหวะการแก้ไข ปรับสไตล์สี หรือจังหวะกดย้อนกลับ (Undo Action) เพื่อนำข้อมูลไปคำนวณบวก/ลบตัวเลขสถิติประวัติการแก้ไข (`layerHistoryCount`) แยกรายชั้นข้อมูลและรายห้องแชท เพื่อเป็นสเตตตั้งต้นให้ระบบจัดเก็บ Undo/Redo ฝั่งแผนที่ทำงานได้อย่างถูกต้อง
  * **เจาะลึกระบบแทรกค่าสไตล์แผนที่ (Dynamic Style Patches):** ดักจับ Event `map_style_patch` เพื่อเปลี่ยนสีลวดลายบนแผนที่สด ๆ ผ่านตรรกะคอมไพล์ไวยากรณ์ (Syntax Editor) ของ MapLibre โดยระบบจะแกะอาร์เรย์โครงสร้างนิพจน์ (Expressions) เช่น สไตล์ `interpolate` หรือ `match` ออกมา แล้วใช้ลูปวิ่งหาตำแหน่งแอตทริบิวต์เพื่อทาสีโค้ดใหม่ทับ หากเป็นตัวเลขใหม่ระบบจะใช้ตรรกะเรียงลำดับ (Sorting) คอยแทรกจุดสลับสีเพื่อให้เลขเรียงจากน้อยไปมากเสมอ
  * **ฉีดแผ่นตัวกรองคุณลักษณะกราฟิก (Map Filter Patches):** ดักจับ Event `map_filter_patch` เพื่อกรองข้อมูลแอตทริบิวต์บนบอร์ดแผนที่แบบเรียลไทม์ โดยหน้าบ้านจะมีระบบคัดกรองจัดกลุ่มประเภทพิกัด (`isSameLayerFamily`) เพื่อจับคู่อินเตอร์เฟสระหว่างคำสั่งที่ส่งมา (เช่น fill, polygon) ให้ตรงกับเอนจินกราฟิกของหน้าจอจริง แล้วฉีดคำสั่ง Filter เข้าไปล็อกการแสดงผลภาพตามเงื่อนไขทันที
  * **แจกแจงทางเลือกและช่องเสิร์ชบน Rich UI (Map Options):** ทำหน้าที่สกัดก้อนคำถาม รายการปุ่มช้อยส์ และสถานะแบ่งหน้า (`pagination`) จาก Event `map_options` แล้วส่งต่อข้อมูลเจาะจงการ์ดข้อความต้นทาง (`targetMessageId`) ทำให้หน้าบ้านสามารถวาดกล่องตัวเลือกและเปลี่ยนรายชื่อเลเยอร์ 4,363 รายการ สลับหน้าไปมาได้ในกล่องข้อความเดิมโดย UI ไม่รกสายตา
  * **สั่งเคลียร์กระดานและล้างสไตล์แผนที่:** ดักจับ Event `map_clear` เพื่อสั่งเคลียร์หน้าจอ โดยแบ่งลอจิกเป็น 2 รูปแบบ คือ ล้างข้อมูลทุกอย่างออกจากจอทั้งหมด (`all`) หรือเลือกเจาะจงลบเฉพาะบางกลุ่มรหัสเลเยอร์ที่ AI ระบุสั่งเคลียร์ (`selected`)
  * **แกะ Buffer แยกขั้นตอนความคิด AI:** คอยตั้งแถบ String Buffer ดักสแกนข้อมูลและแปลงรหัสอักขระ Fragments ด้วย TextDecoder ตลอดเวลา โดยระบบจะสแกนหาแท็ก `<thinking>` เพื่อทำการสไลซ์ตัดเอาขั้นตอนการประมวลผลส่วนลึกออกไปเก็บซ่อนไว้เบื้องหลัง และปล่อยพ่นเฉพาะเนื้อหาสตริงเนื้อ ๆ ออกไปโชว์ในช่องแชทให้ยูสเซอร์อ่านแบบนุ่มนวล

#### 📄 useModels.ts
> **หน้าที่หลัก:** Custom Hook สำหรับจัดการการดึงข้อมูลรายชื่อโมเดล AI (Ollama Models), การแสดงสถานะกำลังโหลด (Loading State) และการควบคุมสลับเปลี่ยนโมเดลที่เปิดใช้งานในระบบแชท

* **กลไกสำคัญ:**
  * **ดึงรายชื่อโมเดลจาก API (Model Fetching):** เรียกใช้งาน `chatService.getModels()` ทันทีเมื่อคอมโพเนนต์เริ่มทำงาน (Mount) เพื่อโหลดข้อมูลรายชื่อโมเดลทั้งหมดที่พร้อมประมวลผลบนเซิร์ฟเวอร์หลังบ้าน โดยมีสเตต `isLoadingModels` คอยส่งสัญญาณให้หน้าจอแสดงผล Loading Placeholder ดักรอไว้ล่วงหน้า
  * **ระบบเลือกโมเดลเริ่มต้นอัตโนมัติ:** หากดึงข้อมูลรายชื่อโมเดลดิบ (`rawList`) มาได้สำเร็จ ระบบจะทำการอัปเดตสเตต `models` และสั่งเปลี่ยนค่า `selectedModel` ไปล็อกเลือกโมเดลตัวแรกสุดในลิสต์ให้โดยอัตโนมัติ เพื่อป้องกันปัญหาการอ้างอิงไอดีโมเดลที่ไม่มีอยู่จริงบนหลังบ้าน
  * **ส่งออกสถานะควบคุม Dropdown:** ทำการรีเทิร์นส่งออกชุดสเตตพร้อมฟังก์ชันเซตค่า (`setSelectedModel`) เพื่อเปิดทางให้คอมโพเนนต์ส่วนหัวแชท (`<Header />`) สามารถนำรายชื่อข้อมูลโมเดล (เช่น ชื่อ และขนาดไฟล์) ไปเรนเดอร์ลงเมนูตัวเลือก Dropdown และกดสลับเปลี่ยนโมเดล AI ที่ต้องการคุยได้ทันที

### 📁 Services

#### 📄 chat.service.ts
> **หน้าที่หลัก:** จัดการเครือข่ายสำหรับระบบสนทนาและคำสั่งแผนที่ (Chat API Client) ทำหน้าที่เป็นเลเยอร์สำหรับเชื่อมต่อและส่งคำขอ (HTTP Requests) ไปยังเซิร์ฟเวอร์หลังบ้านและผู้ให้บริการ GIS ภายนอก โดยห่อหุ้มฟังก์ชันการเรียกใช้งานร่วมกับ `apiClient` และ `axios`

* **กลไกสำคัญ:**
  * **จัดการข้อมูลห้องสนทนา (CRUD):** มัดรวมเมธอดสำหรับควบคุมสถานะห้องแชท ได้แก่ `getHistories` (ดึงรายการห้องแชทพร้อมรองรับการแบ่งหน้า), `renameConversation` (เปลี่ยนชื่อหัวข้อห้อง), `deleteConversation` (ลบเซสชันถาวร) และ `editMessage` (อัปเดตและสั่งประมวลผลคำถามเก่าฝั่งผู้ใช้ซ้ำ)
  * **ดึงประวัติข้อความและเลเยอร์แผนที่เก่า:** เมธอด `getConversationDetail` คอยดักดึงประวัติข้อความเก่าแยกรายห้องตามหมายเลขหน้า (`page`) และเมธอด `getConversationLayers` ทำหน้าที่เรียกคืนสถานะรายการเลเยอร์กราฟิกที่ AI เคยเปิดค้างไว้ในเซสชันนั้น ๆ กลับมาเรนเดอร์ใหม่
  * **ควบคุมลำดับชั้นข้อมูล (Layer Reordering):** เมธอด `updateLayersOrder` ใช้ยิง POST/PATCH ส่งอาร์เรย์รายการชุดรหัสไอดีเลเยอร์ (`layerIds`) เพื่อบันทึกลำดับการซ้อนทับของชั้นข้อมูล (Z-Index) ล่าสุดกลับไปยังหลังบ้าน ป้องกันสไตล์แผนที่แสดงผลทับถมกันเพี้ยน
  * **ยิงเปิดท่อข้อความสตรีมมิ่ง (SSE Stream Connection):** เมธอด `sendMessageStream` ทำหน้าที่คอลอินสแตนซ์พิเศษ `apiClient.stream` เพื่อเปิดท่อเครือข่ายรับข้อความ AI แบบ Real-time Streaming โดยมีกลไกรับกุญแจสิทธิ์ถอนรหัสผูกแนบไปกับ Headers ในชื่อคีย์ `X-API-Key` อย่างปลอดภัย
  * **วิเคราะห์ข้อมูลเชิงพื้นที่ข้ามค่าย:** เมธอด `getLayerAnalytics` ใช้ `axios` ยิงคำสั่งประมวลผลตรงไปยัง API ของผู้ให้บริการแผนที่ (เช่น ค่าย Vallaris) โดยระบบจะดึงเอาเฉพาะ `origin` จาก URL ชั้นข้อมูลดิบมาประกอบโครงสร้างพิกัดปลายทางอัตโนมัติ พร้อมส่งชุด Payload กฎการรวมกลุ่มข้อมูล (`aggregateRules`) และผูก API Key แนบไปกับ Query Parameter เพื่อดึงสถิติจุดความร้อนมาทำกราฟวิเคราะห์

### 📁 Types

#### 📄 index.ts
> **หน้าที่หลัก:** ศูนย์รวมการกำหนดประเภทข้อมูล (Type Definitions) และอินเตอร์เฟส (Interfaces) ทั้งหมดของระบบแชท เพื่อควบคุมความถูกต้องในการรับส่งข้อมูล (Type Safety) ระหว่าง UI คอมโพเนนต์, คลังสเตตส่วนกลาง และระบบสตรีมมิ่งหลังบ้าน

* **กลไกสำคัญ:**
  * **ClarityChoice:** โครงสร้าง Object สากลสำหรับเก็บข้อมูลตัวเลือก (ปุ่มช้อยส์แนะแนวคำตอบ) มีตัวแปร `label` คุมคำแสดงผลบนหน้าจอ และ `value` สำหรับเก็บค่าจริงส่งกลับระบบเมื่อถูกคลิก
  * **Message Object:** โครงสร้างข้อมูลข้อความแชทรายตัว (สลักบทบาทผู้ใช้ด้วย `role`) รองรับระบบ Rich UI เต็มรูปแบบ เช่น อาเรย์รูปภาพที่แนบพิมพ์คำสั่ง (`images`), ลูปวิเคราะห์ความคิด AIเบื้องหลัง (`thinking`), ค่าควบคุมการดักคำถามเพื่อสลับหน้าข้อมูลเลเยอร์ (`choiceKey` และ `choices`) รวมถึงพารามิเตอร์แคชตัวเลขหน้ากระดาษ (`pagination`) สำหรับดักสกรอลล์เปลี่ยนหน้า
  * **ChatThread (ห้องแชท):** พิมพ์เขียวคุมโครงสร้างข้อมูลของห้องสนทนาแต่ละห้อง โดยรวมอาเรย์ก้อนข้อความ (`messages`) ทั้งหมดเข้าไว้ด้วยกัน ผูกตัวแปรบอกแสตมป์เวลาสร้าง/แก้ไขล่าสุด และล็อกคีย์ประเภทสายพันธุ์ของตัวโมดูล AI (`model`) ประจำห้องนั้น ๆ ไว้อ้างอิง
  * **SuggestionItem:** โครงสร้างออบเจกต์คำสั่งคีย์ลัด หรือชิปแนะนำคำถามถัดไปที่บอตส่งมา โดยมี `promptTemplate` เป็นชุดข้อความสำเร็จรูปคอยเตรียมฉีดเข้ากล่องพิมพ์ทันทีเมื่อผู้ใช้กดจิ้มเลือกคำตอบ

### 📄 index.ts (ไฟล์หลักประจำโมดูล)
> **หน้าที่หลัก:** คอมโพเนนต์ออร์เคสเตรเตอร์หลัก (Root Feature Orchestrator) ทำหน้าที่รวบรวมชิ้นส่วนอินเตอร์เฟสทั้งหมด ผูกสเตตและตรรกะควบคุมเครือข่ายเข้าด้วยกัน จัดแจงทิศทางการไหลของข้อมูล (Layout Wrapper) และทำหน้าที่เป็นหน้ากากสาธารณะ (Barrel File) ส่งออกคอมโพเนนต์และฟังก์ชันให้ส่วนอื่นของแอปพลิเคชันดึงไปใช้งาน

* **กลไกสำคัญ:**
  * **ศูนย์กลางกระจายและแลกเปลี่ยนสเตต:** ทำหน้าที่เป็นตัวกลางรับข้อมูลดิบและเมธอดทำงานจาก Custom Hooks (`useChat` และ `useModels`) วิ่งกระจายพ่นแจกจ่ายส่งต่อลงไปเป็น Props ให้คอมโพเนนต์ลูกทั้ง 4 ตัว (`Sidebar`, `Header`, `MessageList`, `ChatInput`) ทำงานสอดประสานกันได้อย่างเป็นระบบ
  * **คัดกรองชุดข้อความเรนเดอร์:** ใช้ประโยชน์จาก `useMemo` ในการประมวลผลตัวแปร `messagesToShow` โดยหากระบบกำลังเปิดห้องแชทหลักอยู่จะดึงอาเรย์ข้อความของห้องนั้นมาวาดภาพ แต่หากผู้ใช้ยังไม่ได้สร้างห้องคุย (สเตตเป็นค่าว่าง) ระบบจะดีดสลับไปพ่นข้อความจากอาเรย์ชั่วคราว (`ephemeralMessages`) แทนออโต้เพื่อไม่ให้หน้าจอเอ๋อ
  * **ระบบล็อกโมเดลประจำเซสชัน:** ดักเช็กสถานะห้องคุยล่าสุดผ่านสเตตคำนวณ `isModelLocked` โดยหากห้องนั้น ๆ เริ่มมีประวัติการประมวลผลคำสั่งกับ AI แล้ว ระบบจะสั่งล็อกสิทธิ์ตัวเลือกถาวรทันทีเพื่อค้ำประกันความเสถียรของบริบท (Context) แต่ออนุญาตให้เปลี่ยนโมเดลได้อย่างอิสระกรณีเป็นเซสชันว่างหรือกลุ่มผู้ใช้โหมดแขก
  * **ระบบทางเลือกโต้ตอบดักตำแหน่งเดิม:** มัดรวมกลุ่มฟังก์ชันการกระทำพิเศษที่ยิงแบบเงียบ (`isSilentRetry`) ได้แก่ `handleSendChoice` (ยิงรหัสโหวตตัวเลือกป้าย), `handleSendPagination` (ส่งขยับพิกัดหน้าแผ่นกระเบื้องเลเยอร์) และ `handleSendSearch` (ส่งคำเสิร์ชฟิลเตอร์เลเยอร์) โดยทั้งแก๊งจะทำการฝังค่า `targetMessageId` ล็อกเป้ากล่องข้อความบอตใบเดิม เพื่อให้ข้อมูลก้อนใหม่ที่สตรีมมาสวมทับตำแหน่งเดิมทันทีโดยไม่สร้างกล่องแชทใบใหม่มาซ้อนรกสายตา
  * **ระบบจัดสรรเซสชันแขกอัตโนมัติ:** ฟังก์ชัน `handleSendMessage` ทำหน้าที่ตรวจสอบเวลาสิทธิ์ใช้งานโหมดแขกก่อนส่งข้อมูล หากตรวจพบว่าเวลาหมดตามเกณฑ์คุกกี้ระบบจะสั่งสลับสถานะเป็นหมดอายุ (`isGuestExpired`) เพื่อล็อกการทำงานหน้าแอปทันที แต่หากตรวจพบว่าเป็นการพิมพ์ครั้งแรกที่ยังไม่มีตั๋วเข้าระบบ โค้ดจะวิ่งไปเรียกใช้เซอร์วิส `initializeGuest` สั่งแอบออกรหัส Guest ID และฝังแสตมป์เวลาเริ่มต้นลงหน่วยความจำ `localStorage` ให้เองแบบเงียบ ๆ ก่อนปล่อยให้ท่อสตรีมข้อความทำงานต่อ
  * **Public API Export Gateway:** ทำหน้าที่เป็นท่อส่งออกสาธารณะประจำคลังโมดูล (Re-exporting) โดยลากชิ้นส่วนภายในทั้งหมดพ่นออกไปข้างนอก เปิดทางให้หน้าหลักระนาบ Root อย่าง `src/app/page.tsx` สามารถ Import เรียกใช้งานป้ายคอมโพเนนต์ `<ChatFeature />` สั้น ๆ ได้ในบรรทัดเดียวอย่างสะอาดตามพิมพ์เขียวแบบ Feature-Based Architecture

#### 📄 ExploreDataModal.tsx
> **หน้าที่หลัก:** หน้าต่างมอดอลป๊อปอัปสำหรับเปิดพื้นที่ทำงานวิเคราะห์ข้อมูลเชิงลึกประจำชั้นข้อมูล (Explore Layer Data Workspace) ทำงานเชื่อมต่อกับระบบคำนวณของ Vallaris โดยตรงเพื่อดึง Schema ค้นหา Attributes และประมวลผลทางสถิติเชิงพื้นที่ออกมาวาดเป็นกราฟจำลอง หรือส่งออกไฟล์ข้อมูล

* **กลไกสำคัญ:**
  * **การคัดกรองเลเยอร์ที่วิเคราะห์ได้:** ตัวมอดอลจะทำการดึงข้อมูลรายการเลเยอร์ทั้งหมดจาก Zustand Store แล้วใช้ฟังก์ชัน `.filter` สกัดเอาเฉพาะชั้นข้อมูลกราฟิกเวกเตอร์ที่มีฐานข้อมูลผูกอยู่จริง เช่น ประเภท `vector_tile`, `pmtiles` หรือ `featureCollection` มาแสดงผลให้ผู้ใช้เลือก
  * **ระบบสแกนสกีมาดึงรายชื่อคุณลักษณะ:** เมื่อเลือกเลเยอร์ ระบบจะนำ `baseUrl` ของเลเยอร์ชุดนั้นไปแกะเอาเฉพาะ `origin` เพื่อวิ่งไปดึงรายชื่อข้อมูลแหล่งจัดเก็บ (Datasources) และลูปดึงรายชื่อคอลัมน์ทั้งหมดจากระบบ Vallaris อัตโนมัติ โดยมีการฝังโครงสร้าง `ANALYTICS_BLACKLIST` เพื่อกรองตัดคอลัมน์ที่ไม่จำเป็นออก (เช่น พิกัด lat/lon หรือแสตมป์เวลา) เหลือเพียงคอลัมน์คุณลักษณะดิบที่พร้อมนำไปคำนวณต่อ
  * **การคำนวณสถิติแยกตามประเภทข้อมูล:** ระบบจะตรวจสอบชนิดข้อมูลอัตโนมัติ หากเป็นคอลัมน์ตัวเลข (`number`) และเลือกโหมด *Global Summary* โค้ดจะทำการยิง POST จัดส่งชุดคำสั่งจับกลุ่มข้อมูล (Aggregate Rules) ไปสั่งให้เอนจินของ Vallaris ประมวลผลหาค่าเฉลี่ย (`avg`), ค่าต่ำสุด (`min`), ค่าสูงสุด (`max`) และจำนวนจุดที่พบ (`count`) ส่งกลับมาให้หน้าบ้านแบบสรุปในแถวเดียว แต่หากเป็นคอลัมน์ข้อความ สลับโหมด หรือเป็นข้อมูลแจกแจง ระบบจะเปลี่ยนไปดึงรายการจัดกลุ่มความถี่แทนโดยล็อกโควตาสูงสุด 10,000 จุด
  * **กลไกวาดกราฟแบบ Native SVG:** เพื่อควบคุมขนาดของแพ็กเกจซอฟต์แวร์ (Bundle Size) หน้าบ้านใช้วิธีคำนวณพิกเซลพล็อตจุดและสเกลความสูงของแท่งกราฟด้วยสูตรคณิตศาสตร์ แล้วใช้แท็ก SVG ตรง ๆ ในการวาดรูป ทั้งแผนภูมิแท่ง (Bar Chart), กราฟเส้น (Line Chart) และแผนภูมิวงกลม (Pie Chart) ที่ใช้เทคนิคคำนวณเส้นรอบวงวงกลม `strokeDasharray` และ `strokeDashoffset` ม้วนพับมุมส่งผลให้ UI ลื่นไหลและประหยัดแรมบราวเซอร์
  * **ระบบถ่ายภาพสแนปช็อตกราฟ (Chart Png Exporter):** ฟังก์ชัน `handleDownloadPng` ทำการแปลงโค้ดโครงสร้างแท็ก SVG ดิบในหน้าจอให้กลายเป็นสตริงข้อความ XML จากนั้นทำการหล่อขึ้นรูปแปลงร่างเป็นก้อน Blob ลิงก์รูปภาพ SVG แล้วนำไปวาดทับลงบนแท็ก `<canvas>` จำลองฝั่งไคลเอนต์ที่มีการถมสีพื้นหลังและเว้นระยะขอบไว้อย่างสวยงาม ก่อนจะสั่งส่งออกเป็นไฟล์ภาพนามสกุล `.png` ให้ผู้ใช้นำไปใส่สไลด์รายงานได้ทันที
  * **ระบบดาวน์โหลด Raw JSON ข้อมูลดิบ:** พัฒนาฟังก์ชัน `handleDownloadJson` คอยดักจับออบเจกต์สถิติที่ได้รับมาจากเครือข่าย นำมาปั่นแปลงร่างผ่านคำสั่ง `JSON.stringify` เพื่อขึ้นรูปเป็นไฟล์ดาวน์โหลดชนิด `application/json` แบบตั้งชื่อระบุแสตมป์เวลาอัตโนมัติเปิดโอกาสให้โปรแกรมเมอร์คัดลอกไปควลคุมประมวลผลต่อได้สะดวก

#### 📄 FeaturePopup.tsx
> **หน้าที่หลัก:** คอมโพเนนต์หน้าต่างป๊อปอัพ สำหรับเปิดแสดงรายละเอียดข้อมูลแอตทริบิวต์ของวัตถุหรือรูปแปลงพิกัดที่ผู้ใช้คลิกเลือกบนแผนที่ รองรับการคลิ้ก ส่งค่า Atribute ข้ามโมดูลส่งต่อกลับไปยังช่องพิมพ์แชท AI ได้โดยตรง

* **กลไกสำคัญ:**
  * **ระบบถอดชื่อหัวข้อออโต้:** ตัวคอมโพเนนต์จะประเมินออบเจกต์ `properties` เพื่อค้นหาคีย์สากลที่เหมาะสมมาเรนเดอร์เป็นชื่อหัวข้อ โดยตรวจสอบตามลำดับความสำคัญ เช่น รหัสภาษาไทยประจำพื้นที่ภูมิศาสตร์ (`pv_tn`, `ap_tn`) หรือคีย์ทั่วไปอย่าง `name` และ `title` พร้อมฝังคุณสมบัติ `truncate` เพื่อตัดคำกรณีข้อความยาวเกินขอบ UI
  * **แผงแสดงรายการแอตทริบิวต์ (Property Grid):** ใช้คำสั่ง `Object.entries` แตกก้อนข้อมูลคุณลักษณะออกมาสแกนแบบลูปคู่คีย์-ค่า (Key-Value) มีระบบดักจับและแปลงค่าว่าง (`null`/`undefined`) ให้กลายเป็นเครื่องหมายขีดค้ำตำแหน่ง (`-`) พร้อมเปิดแถบสกรอลล์จำลองคุมความสูงหน้าต่างไม่ให้บดบังทัศนียภาพของบอร์ดแผนที่หลัก
  * **ท่อฉีดชื่อ Attribute และ Value เข้ากล่องแชท:** ฝัง Event `onClick` แยกฝั่งอย่างชัดเจน โดยเมื่อผู้ใช้คลิกเลือกปุ่มฝั่งซ้าย (Attribute Key) ระบบจะเรียกใช้คำสั่ง `setPendingAttribute(key)` เพื่อส่งชื่อคอลัมน์ดิบข้ามโมดูลไปเสียบต่อท้ายข้อความในช่องพิมพ์แชททันที และหากคลิกปุ่มฝั่งขวา (Value) ระบบจะใช้คำสั่งส่งค่าผลลัพธ์ (`displayValue`) เข้าช่องแชทแทน ช่วยให้ผู้ใช้สามารถคลิกเลือกข้อมูลบนแผนที่ไปสั่งงานพิมพ์ถามคำถามกับ AI ต่อได้ทันทีโดยไม่ต้องเสียเวลาพิมพ์เอง

#### 📄 LayerManager.tsx
> **หน้าที่หลัก:** แผงควบคุมและบริหารจัดการชั้นข้อมูลแผนที่ (Layer Manager Sidebar) รองรับระบบสลับลำดับการซ้อนทับด้วยการลากวาง (Drag and Drop Sorting), สลับการซ่อน/แสดงเลเยอร์และแผนที่ฐาน (Base Map), สั่งกดย้อนกลับการตั้งค่าสไตล์ (Undo Style) และส่งออกสไตล์แผนที่ทั้งหมดเป็นไฟล์คอนฟิกสากล

* **กลไกสำคัญ:**
  * **ระบบลากวางสลับชั้นข้อมูล (Dnd Kit Sorting):** ใช้ชุดเครื่องมือขยาย `@dnd-kit/core` ร่วมกับระบบคัดกรองขอบเขตพิกัด (`modifiers`) เพื่อล็อกทิศทางให้ลากขยับได้เฉพาะแนวตั้ง (`restrictToVerticalAxis`) ภายในขอบเขตคอมโพเนนต์แม่เท่านั้น เมื่อการลากสิ้นสุด (`onDragEnd`) ระบบจะคำนวณตำแหน่งผ่านฟังก์ชัน `arrayMove` เพื่ออัปเดตสเตตกลาง และยิงซิงก์สลับ Z-Index ไปเก็บบันทึกบนฐานข้อมูลหลังบ้านผ่านเมธอด `updateLayersOrder` ทันที
  * **ระบบจำกัดแต้มเพื่อเปิดสิทธิ์ย้อนกลับ (Undo Style Guard):** คอยตรวจสอบและจับคู่ความสัมพันธ์ระหว่างรหัสห้องแชท (`activeChatId`) และรหัสเลเยอร์ปัจจุบันเข้ากับออบเจกต์ประวัติสถิติใน Store (`layerHistoryCount`) โดยระบบจะยินยอมปลดล็อกให้กดปุ่มลูกศรย้อนกลับ (`canUndo`) ก็ต่อเมื่อเลเยอร์นั้นมีจำนวนประวัติการแก้ไขรวมมากกว่า 1 ครั้งขึ้นไป (`currentCount > 1`)
  * **ท่อสะพานคำสั่งส่งย้อนกลับเงียบ (Silent Undo Trigger):** เมื่อผู้ใช้คลิกปุ่มย้อนกลับ ระบบจะส่งไอดีเลเยอร์ผ่านฟังก์ชัน `triggerLayerUndo` วิ่งย้อนศรกลับไปทริกเกอร์ให้ท่อรับส่งข้อความแชทแอบส่งคำสั่งสั่งถอยประวัติสไตล์เงียบ ๆ ไปหา AI หลังบ้านโดยอัตโนมัติ โดยที่ผู้ใช้ไม่ต้องเปิดคีย์บอร์ดมาพิมพ์เอง
  * **ส่งสัญญาณป้าย Mention เข้าแชท:** ฝังตรรกะตรวจจับการคลิกที่ตัวการ์ดเลเยอร์ โดยระบบจะส่งชื่อรหัสเลเยอร์ยิงสวนผ่านฟังก์ชัน `triggerLayerMention` ไปฝากข้อมูลไว้ในสโตร์ส่วนกลาง เพื่อส่งสัญญาณให้ Rich Text Editor ฝั่งกล่องแชท ทำการดึงข้อความไปแปลงร่างฉีดขึ้นโครงสร้างเป็นป้ายแท็ก (Mention Chip Tag) ให้ยูสเซอร์พิมพ์สั่งงานต่อได้ทันที
  * **ดาวน์โหลดชุดคอนฟิกสไตล์แผนที่สากล (Workspace Exporter):** ฟังก์ชัน `handleExportWorkspace` ทำการดึงอินสแตนซ์ของแผนที่จริง (`map`) ออกมาแกะลอกเอาชุดโครงสร้างข้อมูลสไตล์ตัวเต็มด้วยคำสั่ง `map.getStyle()` จากนั้นนำมาจัดฟอร์แมตปั่นขึ้นรูปเป็นไฟล์ดาวน์โหลดชนิด JSON มอบสิทธิ์ให้ผู้ใช้นำไปอัปโหลดเปิดรันบนระบบแผนที่มาตรฐาน MapLibre ที่อื่นได้ทันที

#### 📄 MapDashboard.tsx
> **หน้าที่หลัก:** คอมโพเนนต์เลย์เอาต์หลักสำหรับหน้าจอแผนที่ (Main Map Workspace Layout) ทำหน้าที่เป็นตัวครอบเรนเดอร์ (Wrapper) ชั้นบนสุดเพื่อจัดการพื้นที่พิกเซล พ่วงสถานะ และส่งต่อรายการชั้นข้อมูลเชิงพื้นที่จากสโตร์กลาง ยิงตรงไปให้เอนจินแผนที่ MapLibre GL JS เรนเดอร์กราฟิกออกจอ

* **กลไกสำคัญ:**
  * **ดักจับรายการเลเยอร์แบบเรียลไทม์:** เรียกใช้ Hook ดึงอาเรย์ข้อมูล `dynamicLayers` ออกมาจาก Zustand Store ของระบบแผนที่โดยตรง เพื่อคอยสแกนตรวจจับความเปลี่ยนแปลง หากฝั่งแชท AI มีการนำเข้าเลเยอร์ใหม่ หรือผู้ใช้ใช้แผงควบคุมสลับลำดับ Z-Index ตัวคอมโพเนนต์นี้จะจับสัญญาณและส่งก้อนข้อมูลล่าสุดไปให้เอนจินแผนที่วาดภาพใหม่ทันที
  * **กำหนดค่าเริ่มต้นคุมเอนจินแผนที่:** ทำหน้าที่กระจายพารามิเตอร์และสิทธิ์ควบคุม (Props) ส่งต่อไปให้คอมโพเนนต์ระดับล่าง (`<MapLibre />`) ทำงาน โดยมีการล็อกสิทธิ์บังคับให้โหมดการเรนเดอร์พื้นฐานเป็นเวกเตอร์ (`mapMode={'vector'}`) เพื่อเตรียมโครงสร้าง Canvas ให้พร้อมรองรับท่อส่งสไตล์สีดิบและแผ่น Directives ที่ไหลมาจากระบบหลังบ้านคุยกับ AI ได้อย่างสมบูรณ์แบบ

#### 📄 MapLegend.tsx
> **หน้าที่หลัก:** คอมโพเนนต์แสดงแผงคำอธิบายสัญลักษณ์แผนที่ (Map Legend) ทำหน้าที่สแกนลอกคราบและถอดรหัสสไตล์ (Style Expressions) จากเอนจิน MapLibre GL JS โดยอัตโนมัติ เพื่อจัดทำสเกลสลับเฉดสี หรือแสดงกลุ่มรายชื่อสีจำแนกประเภทตามกลุ่มข้อมูลพื้นที่จริง เรนเดอร์ลอยอยู่บนหน้าจอ

* **กลไกสำคัญ:**
  * **ระบบคัดกรองเลเยอร์ว่าง:** มีการติดตั้งเงื่อนไขตรวจสอบเบื้องต้น หากตรวจพบว่าอาเรย์ชั้นข้อมูลในระบบ (`dynamicLayers`) มีสถานะเป็นค่าว่าง คอมโพเนนต์จะคืนค่า `null` เพื่อระงับการเรนเดอร์กล่องสัญลักษณ์บนหน้าจอทันทีเพื่อไม่ให้ UI บดบังแผงแผนที่หลัก
  * **ถอดรหัสข้อมูลภาพถ่ายทางอากาศ:** กลไกตรวจสอบเงื่อนไขที่ 1 สแกนหาเลเยอร์ประเภท `raster` (เช่น แผนที่ภาพถ่ายดาวเทียม คลังภาพเรดาร์ตรวจอากาศ) เพื่อวาดกล่องคำอธิบายชนิดระบุป้ายข้อมูลภาพถ่ายเชิงพื้นที่แทนการไล่เฉดสี
  * **แกะ paint:** ตัวระบบสามารถวิ่งไปแกะโครงสร้างออบเจกต์ `paint` เพื่อดึงรหัสสีข้ามทุกสายพันธุ์ Geometry บนเว็บได้ทันที (รองรับคีย์สีประเภท fill, fill-extrusion, line, circle และ heatmap) พร้อมทั้งแกะเงื่อนไขจำพวกตรวจสอบสถานะการวางเมาส์ (`case`) ออกไปเพื่อดึงเฉพาะรหัสสีจริงมาแสดงผล
  * **ถอดรหัสสีประเภท Match (การจำแนกกลุ่มแบบแจกแจง):** กลไกตรวจสอบโครงสร้างเงื่อนไขประเภท `match` (เช่น การสลับเฉดสีแยกรายจังหวัดหรือภูมิภาค) ตัวโค้ดจะใช้ลูปกระโดดข้ามดัชนีทีละ 2 พารามิเตอร์ เพื่อสกัดจับคู่ความสัมพันธ์ระหว่างข้อความป้ายและรหัสสีจำลองมาขึ้นรูปเป็นรายชื่อจุดวงกลมสีเรียงต่อกันในกล่องคำอธิบาย
  * **แกะเฉดสี Gradient:** ดักจับไวยากรณ์แผนที่ตระกูลไล่เฉดความร้อนหรือความหนาแน่น (`interpolate` หรือ `step`) เพื่อนำอาเรย์รหัสสีทั้งหมดมาประกอบร่างผ่านคำสั่ง CSS `linear-gradient` พ่นลงบนแท็กหลอดแก้วจำลอง พร้อมระบบตรวจเช็กหากเป็นแผนที่ความหนาแน่น `heatmap` จะดีดข้อความค้ำหัวท้ายเป็นสเกล **Min** ไปจนถึง **Max** อัตโนมัติ คลีนตามลอจิกของเอนจินกราฟิกชั้นสูง

#### 📄 MapLibre.tsx
> **หน้าที่หลัก:** คอมโพเนนต์ Core Map Engine ทำหน้าที่สร้างและควบคุมอินสแตนซ์ของแผนที่ด้วย MapLibre GL JS, ลงทะเบียนโปรโตคอลอ่านไฟล์ pmtiles, จัดการสลับธีมสีพื้นหลัง (Dark/Light Mode) อย่างปลอดภัยโดยไม่ทำลายชั้นข้อมูลเดิม และควบคุมการเรนเดอร์ Popup ของวัตถุที่ถูกคลิกบนแผนที่

* **กลไกสำคัญ:**
  * **การลงทะเบียนโปรโตคอล PMTiles อัตโนมัติ:** ตรวจสอบความพร้อมฝั่งเว็บไคลเอนต์เพื่อเปิดใช้งานคำสั่ง `pmtiles.Protocol()` และนำไปลงทะเบียนเข้ากับเอนจินหลักด้วยคำสั่ง `maplibregl.addProtocol` เปิดทางให้แผนที่สามารถดึงข้อมูลเวกเตอร์แบบแบ่งเซกเมนต์ (Tiles) จากไฟล์คลังข้อมูลขนาดใหญ่ได้โดยตรง
  * **ระบบสลับธีมและรักษาข้อมูล AI:** เมื่อระบบตรวจพบว่าผู้ใช้เปลี่ยนโหมดหน้าจอ (สลับระหว่าง Dark และ Light) แทนที่จะล้างแผนที่ใหม่ทั้งหมด ระบบจะใช้วิธีดึงโครงสร้างสไตล์ปัจจุบันมาแยกแกะเอาเฉพาะ ซอร์สข้อมูล (`ai-source-`) และชั้นข้อมูลสไตล์สีที่สร้างโดย AI (`ai-layer-`) นำไปสอดแทรกฉีดผสมเข้ากับไฟล์โครงสร้าง JSON ของธีมใหม่ก่อนที่จะสั่ง `map.setStyle()` ค้ำประกันให้เลเยอร์แผนที่ของ AI ไม่หายไปในระหว่างสลับโหมดหน้าจอ
  * **ดึงพิกัดระบุตำแหน่งผู้ใช้งาน:** ฟังก์ชัน `handleLocateMe` ดักจับพิกัดละติจูดและลองจิจูดจริงของเครื่องผ่านระบบบราวเซอร์ สั่งเปิดแอนิเมชันร่อนหน้าจอโค้งเข้าหาเป้าหมาย (`map.flyTo`) ที่ระยะซูมระดับ 16 พร้อมปักหมุดมาร์กเกอร์สีแดงระบุสถานะ "คุณอยู่ที่นี่" บนแผนที่ทันที
  * **ควบคุมป๊อปอัพข้อมูลด้วย React DOM:** จังหวะที่มีการคลิกเลือกวัตถุและมีข้อมูล `selectedData` ไหลเข้ามา คอมโพเนนต์จะใช้คำสั่ง `createRoot` สร้างพอร์ทัลเชื่อมข้อมูลพิกเซลแอร์เรียล ไปบังคับเรนเดอร์คอมโพเนนต์ลูก `<FeaturePopup />` ลงบน HTML DOM ที่สร้างขึ้นมาใหม่แบบไดนามิก แล้วสั่งผูกแนบเข้าไปเป็นเนื้อหาภายในป๊อปอัพของ MapLibre โดยมีระบบจำกัดขนาด `maxWidth` และสั่งทำลายล้างหน่วยความจำค้างคา (`root.unmount()`) อัตโนมัติเมื่อป๊อปอัพถูกสั่งปิดลงเพื่อป้องกันปัญหาหน่วยความจำรั่วไหล (Memory Leak)

### 📁 Config

#### 📄 map.config.ts
> **หน้าที่หลัก:** ศูนย์รวมการตั้งค่า คลังจัดเก็บ API Endpoints ของระบบวิเคราะห์ และชุดเครื่องมือประกอบโครงสร้างลิงก์แผนที่สากล (Map URL Builder) ทำหน้าที่รับค่าพิกัดลิงก์ดิบและรหัสไอดีเลเยอร์จากระบบหลังบ้าน นำมาปั่นประกอบร่างเป็นฟอร์แมตที่เอนจินของ MapLibre GL JS อ่านเข้าใจตามมาตรฐานสากลของแต่ละชนิดข้อมูล (GIS Protocols)

* **กลไกสำคัญ:**
  * **เครื่องมือจัดทำลิงก์โครงสร้างไทล์:** มัดรวมเมธอดสำเร็จรูปประจำ Geometry แต่ละประเภท (เช่น `tms`, `vector` และ `coverage_tile`) โดยระบบมีลอจิกคอยตรวจจับอัตโนมัติ หากตรวจพบว่าพิกัด URL ดิบยังไม่มีแท็กตัวแปรคุมระยะซูมและตำแหน่งพิกเซล โค้ดจะทำการเติมต่อท้าย Path ให้เองในรูปแบบมาตรฐาน `/{z}/{x}/{y}` เพื่อเปิดท่อให้อินสแตนซ์แผนที่สามารถคำนวณดึงรูปแผ่นกระเบื้องแผนที่ตามระยะการซูมเข้า-ออกของยูสเซอร์ได้ถูกต้อง
  * **ระบบแปลงรูปแบบจัดส่งภาพ WMS:** เมธอด `wms` ทำหน้าที่แปลงโครงสร้างพิกัดแผนที่ประเภท Web Map Service (WMS) โดยฉีดพารามิเตอร์บังคับระดับสากล เช่น บังคับประเภทเซสชันให้ส่งผลลัพธ์กลับมาเป็นภาพถ่ายโปร่งแสงเนื้อไฟล์เพรียวบาง (`FORMAT=image/png&TRANSPARENT=true`), ระบุระบบพิกัดอ้างอิงเชิงพื้นที่สากล (`SRS=EPSG:3857`), บังคับขนาดกว้างยาวของรูปแผ่นที่ย่อยไว้ที่ `256x256` พิกเซล พร้อมฝังท่อตัวแปรกล่องขอบเขตพิกัดภูมิศาสตร์ `{bbox-epsg-3857}` เพื่อให้เอนจินสุ่มเรนเดอร์ภาพถ่ายดาวเทียมขยับพิกัดตามหน้าจอจริง
  * **ตัวถอดรหัสและแปลงพิกัดตระกูล WMTS:** เมธอด `wmts` คอยดักจับสแกนพิกัดชั้นข้อมูลชนิด Web Map Tile Service (WMTS) โดยเพิ่มกลไกเช็กความปลอดภัย หากตรวจพบว่าลิงก์เคยโดนเข้ารหัส URL สัญลักษณ์วงเล็บปีกกามาในฟอร์แมต `%7Bz%7D` โค้ดจะสั่งรันเมธอด `decodeURIComponent` คืนร่างกลับเป็นข้อความดิบให้อ่านง่ายทันที พ่วงลอจิกคัดแยกค่ายคอยถอดสไตล์ หากพบว่ามาจากระบบ Vallaris จะสลับร่างดึงเฉพาะภาพ `.png` ตรง ๆ แทนการพ่นชุด Query พารามิเตอร์ขยะ
  * **ระบบครอบโปรโตคอลแผนที่ PMTiles:** เมธอด `pmtiles` ทำหน้าที่อำนวยความสะดวกในการเชื่อมระบบอ่านไฟล์บิ๊กดาต้าแผนที่เชิงพื้นที่ขนาดใหญ่ โดยทำระบบตรวจจับคำขึ้นต้น หากพบว่าลิงก์ต้นทางยังไม่ได้เซตชื่อสิทธิ์เครือข่าย โค้ดจะทำการฉีดโปรโตคอลพิเศษฝังหัวแถวในรูปแบบ `pmtiles://` เข้าไปค้ำหน้าให้ทันที เพื่อส่งสัญญาณกระตุ้นให้เอนจิน MapLibre ดึงไฟล์ส่วนเสริม (Protocol Plugin) ออกมาใช้งานได้อย่างถูกต้องแม่นยำ
  * **คลังระบุ Endpoints ระบบวิเคราะห์เชิงพื้นที่:** โครงสร้างออบเจกต์ `MAP_CONFIG` จัดเก็บพิกัดเนมสเปซเครือข่ายสำหรับยิงข้ามค่ายไปหาเซิร์ฟเวอร์ Vallaris เพื่อให้มอดอลเจาะสถิติบิ๊กดาต้า (`<ExploreDataModal />`) สามารถคอลเรียกใช้ฟังก์ชันประกอบ Path ในการสแกนหา Datasources และ คอลัมน์คุณลักษณะ (`columns`) รวมถึงการ POST ก้อน Payload ไปประมวลผลคำนวณสถิติที่ท่อกลาง (`explore`)

### 📁 Hooks

#### 📄 useDynamicLayers.ts
> **หน้าที่หลัก:** Custom Hook ศูนย์กลางจัดการเลเยอร์แผนที่ คอยสั่งเพิ่ม อัปเดต หรือลบชั้นข้อมูลประเภทต่าง ๆ (WMS, TMS, WMTS, Vector Tile, PMTiles, GeoJSON) ลงบนแผนที่ตามคำสั่งของ AI พร้อมควบคุมลำดับการซ้อนทับ (Z-Index) และเปิด-ปิดการมองเห็นเลเยอร์

* **กลไกสำคัญ:**
  * **ตัวประกอบ URL แยกตามประเภทแผนที่:** เช็กประเภทเลเยอร์ออโต้เพื่อต่อ URL ให้เข้ากับมาตรฐานแผนที่สากล เช่น ถ้าเป็น WMTS จะบังคับขนาด Tile Size เป็น 512 ค่ายอื่นเป็น 256 และคอยฉีดโปรโตคอล `pmtiles://` นำหน้าลิงก์ให้เองเพื่อให้ MapLibre อ่านไฟล์ PMTiles ได้
  * **ดักดักเช็ก API Key ฝั่ง Vallaris:** ตรวจสอบความปลอดภัยของเลเยอร์ที่ดึงมาจากค่าย Vallaris ถ้าในสโตร์กลางยังไม่มี API Key ผูกอยู่เลย ระบบจะสั่งระงับการแอดเลเยอร์นั้นทันทีเพื่อไม่ให้ระบบแครช
  * **ระบบสลับสไตล์เวกเตอร์แบบเรียลไทม์:** คอยสแกนดูว่า AI ส่งโครงสร้างสีหรือสไตล์ใหม่มาไหม โดยนำก้อนคอนฟิกมาแปลงเป็นข้อความสัญกรณ์จำลอง (`appliedFlag`) เพื่อเช็กความเปลี่ยนแปลง ถ้าสไตล์ไม่เหมือนเดิม ระบบจะสั่งลบเลเยอร์ย่อยตัวเก่าทิ้งแล้วแอดสไตล์ใหม่เข้าไปสวมแทนทันทีโดยไม่ต้องรีโหลดแผนที่ใหม่
  * **ตัวแยกประเภท Geometry:** ตรรกะสแกนหาค่า `type` หรือ `layerType` ของข้อมูลเวกเตอร์ เพื่อแยกส่งพารามิเตอร์ไปแอดเป็น Layer ย่อยบน MapLibre ให้ถูกต้องตามรูปทรงจริง แบ่งเป็น 4 ประเภท คือ พื้นที่ปิดแปลงที่ดิน (`fill`), เส้นทาง/ถนน (`line`), จุดความร้อน/พอยต์ทั่วไป (`point`) และตึกสามมิติ (`fill-extrusion`)
  * **สไตล์สำรองกรณี AI ขาดชุดคำสั่งพ่นสี:** ถ้าเลเยอร์เวกเตอร์ไหลเข้ามาแต่ AI ไม่ได้แถมคอนฟิกพ่นสีมาด้วย หน้าบ้านจะแอดเลเยอร์ย่อยค้ำไว้ให้เอง 3 ตัวทันที (Fill, Line, Heatmap) พร้อมฝังคำสั่งตรวจจับการเอาเมาส์ไปชี้ (Hover) ให้สลับเปลี่ยนเป็นสีเหลืองไฮไลต์ `#facc15` โต้ตอบกับผู้ใช้ได้ออโต้
  * **โฟกัสกึ่งกลางข้อมูลแผนที่:** ตรวจสอบว่าไฟล์แผนที่ที่นำเข้ามามีพารามิเตอร์ขอบเขตพื้นที่ (`bounds`) ติดมาด้วยไหม ถ้ามี ระบบจะสั่งรันเมธอด `.fitBounds` บินร่อนหน้าจอรวดเดียวเข้าไปจับโฟกัสซูมให้เห็นตัวข้อมูลกึ่งกลางจอทันที
  * **ระบบล้างขยะหน่วยความจำ:** เปรียบเทียบไอดีเลเยอร์ล่าสุดกับประวัติในอาร์เรย์ `activeLayerIds` ถ้าเจอเลเยอร์เก่าตกค้าง (เช่น ผู้ใช้กดลบห้องแชท หรือ AI สั่งล้างกระดาน) ระบบจะตามไปลบ Layer และ Source ออกจากแผนที่ทันทีเพื่อคืนแรมให้บราวเซอร์
  * **ระบบจัดลำดับเลเยอร์ AI ค้ำไว้บนสุด:** ฟังก์ชันจัดเรียงลำดับการซ้อนทับของภาพบนจอ โดยรันลูปถอยหลังจากท้ายอาเรย์ (Reverse Loop) เพื่อคอลคำสั่ง `.moveLayer` ดีดกลุ่มเลเยอร์ที่ AI สร้างไปกองไว้ชั้นบนสุดเสมอ เพื่อไม่ให้โดนแผนที่ฐาน (Base Map) บดบัง
  * **ตัวสลับเปิด-ปิดเลเยอร์ และแผนที่ฐาน:** วนลูปแยกฝั่งควบคุมการมองเห็นหน้าจออย่างชัดเจน โดยถ้าเป็นเลเยอร์ AI จะไปเช็กชื่อจากลิสต์ `hiddenLayers` เพื่อสั่งซ่อน/แสดงตามปุ่มที่ผู้ใช้กด แต่ถ้าเป็นตัวแผนที่หลังบ้านจะคุมผ่านตัวแปร `isBaseMapVisible`
  * **ตัวล็อกเลเยอร์ไม่ให้หายจังหวะสลับโหมดมืด/สว่าง:** ดักจับเหตุการณ์เปลี่ยนธีมพื้นหลังแอป (`styledata`) ของ MapLibre เพื่อสแกนดูว่าเลเยอร์ของ AI โดนระบบล้างหลุดไปไหม ถ้าหลุดหายไป โค้ดจะสั่งเคลียร์คิวและแอดชั้นข้อมูล AI ถ่มกลับเข้าไปเติมให้ใหม่ทันทีแบบไร้รอยต่อ

#### 📄 useMapEvents.ts
> **หน้าที่หลัก:** Custom Hook สำหรับดักจับเหตุการณ์ต่าง ๆ บนแผนที่ (Map Events) เช่น การคลิกเมาส์ การเลื่อนเมาส์ผ่านวัตถุ เพื่อสั่งเปิดหน้าต่างป๊อปอัพโชว์ข้อมูลแอตทริบิวต์ และสั่งเปลี่ยนสถานะไฮไลต์สีวัตถุแบบเรียลไทม์

* **กลไกสำคัญ:**
  * **ระบบเคลียร์สีไฮไลต์ย้อนหลัง:** ฟังก์ชัน `clearHighlight` ทำหน้าที่ล้างสถานะไฮไลต์ของวัตถุชิ้นเก่า โดยใช้คำสั่ง `map.setFeatureState` เปลี่ยนค่าสเตต `hover` กลับไปเป็น `false` ทันทีที่ผู้ใช้ปิดป๊อปอัพ หรือเลื่อนเมาส์หนีออกจากพื้นที่เดิม เพื่อป้องกันปัญหาสีไฮไลต์ค้างบนแผนที่
  * **มัดรวมรายชื่อเลเยอร์ AI ดักฟังเหตุการณ์:** ใช้คำสั่ง `flatMap` เพื่อนำรายการไอดีเลเยอร์ของ AI ทั้งหมดในระบบมาแตกแขนงพ่วงนามสกุลรูปทรงซ้อนกัน 4 เลเยอร์ย่อยต่อ 1 ชุดข้อมูล (ประกอบด้วยแปลงที่ดิน `-fill`, เส้นถนน `-line`, จุดพอยต์ `-point` และตึกสามมิติ `-fill-extrusion`) เพื่อนำลิสต์ไอดีชุดนี้ไปใช้สั่งดักฟังเหตุการณ์เมาส์คลิกและเมาส์เลื่อนผ่านพร้อมกันทั้งหมด
  * **ระบบคลิกจับวัตถุบนแผนที่:** เมื่อเกิดเหตุการณ์คลิกแผนที่ (`handleMapClick`) โค้ดจะใช้เมธอด `map.queryRenderedFeatures` สแกนหาวัตถุที่ตรงกับพิกเซลปลายเมาส์เฉพาะบนเลเยอร์ของ AI ถ้าเจอวัตถุชิ้นนั้น ระบบจะล็อกรหัสไอดี สั่งทาสีไฮไลต์สเตต `hover: true` และส่งก้อนข้อมูลพิกัดเชิงพื้นที่พ่วงแอตทริบิวต์ขึ้นไปบันทึกที่ `setSelectedData` เพื่อสั่งวาดป๊อปอัพเปิดกางออกทันที
  * **ระบบเลื่อนเมาส์ชี้เปลี่ยนสีสลับเคอร์เซอร์:** ในฟังก์ชัน `handleMouseMove` หากป๊อปอัพยังไม่ได้เปิดกางออก จังหวะที่ผู้ใช้เลื่อนเมาส์ไปชี้โดนแปลงที่ดินหรือวัตถุของ AI ระบบจะสั่งเปลี่ยนหน้าตาเคอร์เซอร์เมาส์บนแผ่น Canvas ให้กลายเป็นรูปมือจิ้ม (`pointer`) ทันที พร้อมสั่งยิงสถานะเปลี่ยนสีไฮไลต์สลับตามชิ้นวัตถุที่เมาส์วิ่งผ่านแบบเรียลไทม์
  * **กลไกหยุดล็อกสถานะเมื่อป๊อปอัพทำงาน:** ใช้ตัวแปร Ref `isPopupOpen.current` คอยดักจับสถานะ หากตรวจพบว่าหน้าต่างป๊อปอัพข้อมูลกำลังเปิดกางคาหน้าจออยู่ ระบบจะสั่งข้าม (Abort) ลอจิกการเลื่อนเมาส์เปลี่ยนสีไฮไลต์ทั้งหมดทันที เพื่อล็อกล็อกเป้าหมายให้สีไฮไลต์ค้างอยู่ที่วัตถุชิ้นที่ผู้ใช้จิ้มเลือกอยู่ล่าสุด ไม่ให้สีวิ่งกระพริบตามเมาส์

### 📁 Services

#### 📄 map.service.ts
> **หน้าที่หลัก:** เซอร์วิสสำหรับประกอบและจัดการ URL ของเลเยอร์แผนที่ (Map URL Builder Service) ทำหน้าที่รับก้อนข้อมูลเลเยอร์พ่วงคลัง API Key จาก Store มาคำนวณแจกแจง เติมพารามิเตอร์เครือข่าย และแนบกุญแจสิทธิ์การเข้าถึงให้ตรงตามมาตรฐานของแต่ละผู้ให้บริการแผนที่ก่อนส่งไปให้เอนจินวาดภาพ

* **กลไกสำคัญ:**
  * **ระบบกุญแจอัจฉริยะ:** มีฟังก์ชัน `appendApiKey` คอยสแกนตรวจสอบโครงสร้างลิงก์ปลายทาง หากพบว่าลิงก์มีการแปะพารามิเตอร์ Query สตริงตัวอื่นคาอยู่ก่อนแล้ว (`?`) ระบบจะใช้เครื่องหมาย `&` ในการเชื่อมต่อท้ายคีย์ `api_key` แต่หากเป็นลิงก์เปล่าจะใช้เครื่องหมาย `?` นำทางให้เองโดยอัตโนมัติ เพื่อไม่ให้ไวยากรณ์ URL พัง
  * **ตัวเลือก Provider และสลับกุญแจอัตโนมัติ:** ตรรกะตรวจสอบเนมสเปซเครือข่าย โดยระบบจะตั้งค่าเริ่มต้นในการดึงคีย์เป็นฝั่ง GISTDA แต่หากวิ่งไปดักเจอคำว่า `vallaris` ในชื่อผู้ให้บริการหรือตัวลิงก์ดิบ ระบบจะทำการดีดสลับร่างหันไปคว้าเอา API Key ฝั่ง Vallaris มาเปิดสิทธิ์สวมรอยให้เองทันที
  * **ระบบล้าง URL Decoding:** ทำการรันคำสั่ง `decodeURIComponent` ครอบลิงก์ `baseUrl` ตั้งแต่บรรทัดแรกสุด เพื่อแปลงรหัสขยะหรือตัวอักษรพิเศษที่มักจะโดนบราวเซอร์เข้ารหัสติดมา (เช่น คีย์ระยะซูมแผนที่ที่โดนแปลงรูปเป็นข้อความเปอนเซ็นต์) ให้คืนร่างกลับมาเป็นตัวอักษรสากลที่ระบบอ่านเข้าใจ
  * **ตัววิ่งกระจายท่อคอลสลับฟอร์แมต:** ใช้โครงสร้างคำสั่ง `switch (type)` ทำหน้าที่เป็นแผงวงจรคอยกระจายท่อส่ง โดยจะเช็กชื่อชนิดโปรโตคอลแผนที่ที่ส่งเข้ามา (เช่น tms, wmts, vector_tile, geojson, pmtiles) แล้วเลือกโยนลิงก์ดิบส่งต่อไปให้ฟังก์ชันเฉพาะทางในโมดูล `mapUrlBuilder` คลี่โครงสร้างจัดฟอร์แมตเติมแท็กระยะซูม `/{z}/{x}/{y}` ให้ตรงสายงาน

### 📁 Types

#### 📄 index.ts
> **หน้าที่หลัก:** คลังรวบรวมประเภทข้อมูลและอินเทอร์เฟซหลักประจำฟีเจอร์แผนที่ ทำหน้าที่กำหนดมาตรฐานและโครงสร้างข้อมูลเชิงพื้นที่เพื่อให้ทุกคอมโพเนนต์, ฮุก, และเซอร์วิสในโปรเจกต์เข้าใจตรงกัน ป้องกันการส่งข้อมูลผิดฟอร์แมตระหว่างหน้าบ้านและหลังบ้าน

* **กลไกสำคัญ:**
  * **กลุ่มกำหนดค่าคงที่ของแผนที่:** ประกาศประเภทข้อมูลคุมค่าคงที่ที่ระบบยอมรับ เช่น ช่วงเวลาวิเคราะห์ (`TimeRange` จำกัดที่ 1, 3, 7, 30 วัน), ประเภทภัยพิบัติ (`HazardType` เช่น ไฟป่า viirs, น้ำท่วม flood, ภัยแล้ง drought) และโหมดมาตรฐานแผนที่สากล (`MapMode`) เพื่อใช้เป็นตัวกรองลอจิกหน้าบ้าน
  * **โครงสร้างรับข้อมูลสตรีมมิ่ง:** ตัวอินเทอร์เฟซรองรับข้อมูลดิบในจังหวะที่ AI หรือเซิร์ฟเวอร์ยิงสตรีมข้อมูลแผนที่เข้ามา โดยกำหนดให้ระบุประเภทแผนที่ (`type`), ลิงก์ปลายทาง (`url`), และชื่อเลเยอร์ต้นทาง (`layerName`) เป็นค่าบังคับ พร้อมรองรับพารามิเตอร์สั่งเคลื่อนไหวกล้องบนแผนที่ (`mapAction`)
  * **โครงสร้างจัดเก็บข้อมูลเลเยอร์แบบไดนามิก:** ตัวควบคุมโครงสร้างข้อมูล (Payload) ของเลเยอร์ที่ฮุก `useDynamicLayers` บังคับใช้ โดยเก็บค่าไอดีสำหรับใช้อ้างอิงสั่งลบขยะความจำ (`id`), คีย์คัดแยกค่ายผู้ให้บริการสิทธิ์กุญแจ (`apiProvider`), อาเรย์คุมขอบเขตภูมิศาสตร์ 4 พิกัด (`bounds`) สำหรับสั่งบินหน้าจอออโต้ รวมถึงลิสต์เก็บสถานะสลับสไตล์พ่นสีเวกเตอร์ (`renderStyles`, `availableStyles`, `activeStyleKey`) ที่ได้มาจาก AI
